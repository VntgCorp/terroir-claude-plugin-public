# terroir-onboarding 변경 이력

실제 배포 버전은 [`.claude-plugin/plugin.json`](.claude-plugin/plugin.json)을 따른다.

## 1.2.0 - 2026-10-01

### 추가

- 업무 지도(`/work-map`)를 더해, 자주 쓰는 프로젝트·채널·동료·레포를 등록해 두면 새 세션에서 Claude 가 찾지 않고 바로 쓰게 했습니다.
- 업무 지도가 없을 때 지라 티켓·채널·동료·레포·드라이브 문서를 찾아 달라고 하면, 응답 끝에 업무 지도 등록을 한 줄로 안내하도록 했습니다.
- 온보딩에서 이메일과 채팅·메일에 쓸 본인 이름, 실제 직무를 업무 지도에 저장하는 단계를 더했습니다.
- 업무 도구 연결 안내를 따라 도구를 새로 연결하면, 다음 세션에서 그 도구로 업무 지도 후보를 찾을지 한 번 묻도록 했습니다.

### 변경

- 온보딩을 시작하면 첫 안내가 나오기까지 한동안 아무것도 보이지 않던 것을, 시작 인사가 먼저 나오도록 바꿨습니다.
- 온보딩 중 재시작하거나 `/onboarding` 을 다시 실행하면 직무를 다시 묻던 것을, 저장해 둔 이름·직무로 이어 가도록 바꿨습니다.

## 1.1.1 - 2026-09-28

### 추가

- **§0-1 설치된 것 소개.** 자동 업데이트 안내 다음, 직무 확인 앞에서 공개 마켓플레이스의 플러그인 3개가 무엇을 하는지 한 번 출력한다. skill 단위는 적지 않는다 — 온보딩이 이어서 부르고, 따로 부를 일이 생기면 그 자리에서 안내한다. 사용자는 위키 안내를 따라 무엇인지 모른 채 설치 명령을 실행하고 들어오는데, 그때까지 어디에서도 설명을 받지 못했다. 재시작 이어받기(§4)와 종료 출력 단독 실행(§3)에서는 내지 않는다 — 이미 본 화면이거나 온보딩을 마친 사람이다 [RDDP-1797].

## 1.1.0 - 2026-09-22

### 추가

- **`github-connect` §4-1 — SSO 승인 확인.** 조직 멤버십이 `active` 인데 private 레포가 404 면 `org-access-request` 로 보내지 않고 먼저 토큰의 조직 SSO 승인을 시도한다. `gh auth refresh` 를 백그라운드로 실행해 8자리 코드를 전달하고, **VntgCorp 조직의 `Authorize` 버튼까지 눌러야 한다**는 것을 안내한 뒤 턴을 끊고 기다린다 [RDDP-1695].
- **`org-access-request` §1 에 2단계 인증(2FA) 안내.** 조직이 2FA 를 요구해 켜기 전에는 초대를 수락할 수 없고, 가입 후 해제하면 조직에서 제외된다. 이 안내가 없으면 사용자가 초대 메일을 받고도 수락에서 막히고, 그 이유가 화면에 드러나지 않는다 [RDDP-1695].

### 변경

- `active` + 404 를 더 이상 "레포 권한 없음"으로 단정하지 않는다. 이 조합의 가장 흔한 원인은 권한 부족이 아니라 SSO 미승인인데, 그대로 분기하면 담당자에게 보낼 필요가 없는 사용자를 보내게 된다. SSO 승인 뒤에도 404 인 경우만 `org-access-request` 로 넘긴다.
- 이어받기(승인 후 재개)에서 `active` 인데 실패하면 §4-1 을 먼저 거친다 — 초대를 막 수락한 직후라 토큰에 조직 승인이 아직 없는 것이 이 시점의 가장 흔한 원인이다. "몇 분 후 재시도"는 그 뒤로 미룬다.

### 제거

- **사내 Confluence GitHub 가이드 링크**(`github-connect` · `org-access-request` 각 1곳). 가리키던 문서가 GA 폴더로 정리되면서 원문은 히스토리로만 남는다. 두 스킬이 가입·2FA·조직 등록부터 설치·인증·접근 확인까지 절차를 모두 갖고 있어 링크 없이 완결된다 [RDDP-1695].

## 1.0.2 - 2026-09-17

### 추가

- 온보딩 공통 종료 출력 끝에 마무리 두 줄을 붙인다 — `/reload-plugins` 안내와, 리로드 뒤 "떼루아에서 무엇을 할 수 있지?" 라고 물으라는 다음 발화 안내. 스타트 포인트가 설치된 경로(표가 떴거나, 설치됐는데 세션에 안 보이는 경우)에서 출력한다.

### 변경

- 리로드 안내를 마무리 두 줄이 단독으로 갖는다. "설치됐는데 세션에 안 보임" 분기는 상태만 알리고 리로드를 다시 지시하지 않는다 — 한 화면에 같은 지시가 두 번 나오지 않는다.
- 리로드 안내를 조건절("아직 안 보이면")로 둔다. 스타트 포인트가 이미 보이는 사용자에게 할 일이 없는 동작을 지시하지 않는다.
- 스타트 포인트가 설치되지 않은 화면(비 프로덕트 직군 · 설치 전)에서는 두 줄을 내지 않는다. 물음을 받아줄 시작 안내 스킬이 없어 같은 화면이 되돌아오기 때문이다.

## 1.0.1 - 2026-09-02

### 추가

- `/onboarding` 시작 시 public `terroir-claude-plugin-public` 마켓플레이스의 사용자 전역 자동 업데이트를 활성화한다.
- 프로덕트 직군이 private 플러그인 설치까지 진행하면 private `terroir-claude-plugin` 마켓플레이스의 자동 업데이트도 활성화한다.
- 설정을 변경했는지, 이미 활성화되어 있는지, 수동 설정이 필요한지를 사용자에게 안내한다.

### 변경

- 기존 설정과 마켓플레이스 채널을 보존하며, 자동 업데이트 설정에 실패해도 나머지 온보딩을 계속한다.

## 1.0.0 - 2026-08-28

최초 배포.

### 추가

- `/onboarding` — 직무와 업무 도구 연결 상태에 따라 온보딩을 분기하고, 설치된 private 플러그인의 시작점을 안내한다.
- `/env-setup` — 지라·컨플루언스, 이메일·캘린더·드라이브 등 공통 업무 도구 연결을 점검한다.
- `/github-connect` — GitHub 계정·Git 연결과 private 플러그인 설치를 진행한다.
- `/org-access-request` — 조직 접근 권한이 없을 때 요청 폼과 대기 안내를 제공한다.

참고: 버전을 붙이기 전 배포본의 진입 스킬 이름은 `/onboarding-start`였다. 플러그인 이름은 같아 재설치 없이 업데이트로 반영된다.
