# 떼루아에게 질문하기

플러그인을 깔고 나면 명령어를 외울 필요가 없습니다. 하고 싶은 말을 그대로 하면 됩니다 — “새 프로젝트 시작하고 싶은데”, “배포가 안 열려”, “왜 느리지”. 설치부터 어떤 질문을 할 수 있는지 알아봅니다.

플랫폼개발팀 2026-10 읽는 데 4분

01

## 설치는 세 줄이면 끝납니다

공개 마켓플레이스 하나만 등록하면 됩니다. GitHub 로그인도 조직 가입도 필요 없습니다. 사내 플러그인은 그다음 온보딩이 알아서 설치합니다.

1

마켓플레이스 등록

Claude Code 입력창에 그대로 붙여넣습니다.

```
/plugin marketplace add VntgCorp/terroir-claude-plugin-public
```

2

플러그인 설치 후 리로드

설치는 말로 부탁하면 됩니다. 클로드가 마켓플레이스 목록을 확인해서 설치합니다.

```

terroir-claude-plugin-public 마켓플레이스의 플러그인 User 설정에 모두 설치해줘
```

설치한 것을 지금 세션에 반영합니다.

```
/reload-plugins
```

/plugin → Installed 에서 terroir-onboarding 을 고르면 skill 4개가 보입니다.

3

온보딩 실행

여기서부터는 대화입니다. 소프트웨어를 만드는 일을 하는지와 직무를 묻고, 업무 도구를 연결하고, 「소프트웨어 개발」을 고르면 사내 플러그인까지 깔아 줍니다.

```
온보딩 시작해줘
```

다시 실행해도 괜찮습니다

온보딩은 상태를 먼저 확인하고 없는 것만 설치합니다. 중간에 끊겨도 다시 실행하면 끝난 단계는 건너뜁니다.

위 프롬프트의 User 설정은 설치 범위입니다 — 이렇게 깔면 내 컴퓨터의 모든 폴더에서 쓸 수 있습니다.

02

## 첫 질문은 이것 하나면 됩니다

온보딩을 마친 다음, 무엇부터 할지 모르겠다면 그냥 물어보세요.

```
떼루아에서 무엇을 할 수 있지?
```

설치된 도구와 연결 상태를 훑어서 지금 이 사람이 할 수 있는 일만 골라 보여줍니다 — 소프트웨어를 만드는 과정과 연결한 업무 도구, 두 갈래입니다.

「소프트웨어 개발」을 고른 사람 — 소프트웨어 만드는 전 과정

화면이 좁으면 가로로 밀어서 봅니다

KICKOFF → PLANNING → HANDOFF → DEVELOPMENT → DEPLOYMENT → OBSERVABILITY. 칸마다 무엇을 할 수 있고(· 기능) 무엇이 나오는지(⇒ 결과물)가 함께 적힙니다 — 기획이 끝나면 PRD · FRD · 시안 이, 배포가 끝나면 이미지 · 파이프라인 이 남습니다. 맨 아래 줄은 업무 도구와 포털 연결을 어디서 확인하는지 알려 줍니다.

업무 도구 연결한 것으로 할 수 있는 일

커넥터마다 “이렇게 말해보세요” 예시가 함께 나옵니다. 그대로 물어보면 됩니다. 「일반」을 고른 사람은 이 표만 나옵니다 — GitHub 도 프로젝트도 없이 연결된 도구만으로 쓸 수 있습니다.

고른 답에 따라 다르게 나옵니다

두 화면은 같은 한 문장에서 나왔습니다. 온보딩이 소프트웨어를 만드는 일을 하는지 먼저 묻고, 설치된 플러그인과 연결된 커넥터를 확인한 뒤 그 사람에게 해당하는 것만 남깁니다. 쓰지 않을 도구를 권하지 않고, 써야 하는데 빠진 것은 어디서 연결하는지 알려 줍니다.

답을 잘못 골랐거나 맡은 일이 바뀌었다면 `지도 고쳐줘` 로 프로필을 바꾼 뒤 `온보딩 시작해줘` 를 다시 실행하면 됩니다. 처음부터 다시 하지 않습니다 — 이미 끝난 단계는 건너뜁니다.

03

## 무엇을 물어볼 수 있나

아래 예시는 그대로 쓰지 않아도 됩니다. 비슷하게만 말해도 알아듣습니다.

차례는 앞에서 본 여섯 단계 그대로 — 소프트웨어를 만드는 쪽 이야기입니다. 기획 · 문서 작업이 중심이라면 앞 절 커넥터 표의 예시가 대부분을 차지합니다.

그리고 뒤로 갈수록 앞 단계의 결과물이 필요합니다 — 배포를 물으려면 이미지가, 운영을 물으려면 배포된 서비스가 있어야 합니다.

시작 project-guide · kickoff

- 떼루아에서 뭘 할 수 있지?
- 새 프로젝트 시작하고 싶은데
- 기존 작업을 떼루아에서 하려면

설치 직후 바로

기획 planning

- 요구사항 정리해줘
- 이 기능 스펙 써줘
- 기획 뭐부터 해야 하지

설치 직후 바로 — 저장소가 없어도 됩니다

디자인 design-flow

- 화면 그려줘
- 시안 고치고 싶어
- 디자이너가 그린 시안 가져와줘

Claude Design 연결 — 없으면 연결부터 안내합니다

넘기기 handoff

- 개발로 넘기자
- 산출물 올려줘
- PR 코멘트 달렸는데

넘길 산출물이 있어야 — 저장소 밖에 있으면 옮길 자리부터 확인합니다

개발 development · context

- 표준 뭐 있어
- 컨테이너 이미지로 만들어줘
- 이 서비스에 트레이스 붙여줘

“표준 뭐 있어”는 바로 — 나머지 둘은 프로젝트 저장소 안에서

배포 deployment

- 배포하려고 해
- 포트 바꿔줘
- 워크로드 추가해줘

컨테이너 이미지가 있어야 — 없으면 “컨테이너 이미지로 만들어줘” 부터

운영 observability

- 서비스 상태 봐줘
- 지금 정상이야?
- 오류 나는데 어디가 문제야

배포 + 트레이싱이 붙은 서비스 — 없으면 “트레이스 붙여줘” 부터

막혔을 때 증상 그대로

- 권한이 없다는데
- 머지했는데 배포가 안 돼
- 포털에 앱이 안 보여

설치 직후 바로 — 어느 단계에서든

04

## 도구를 붙이면 묻는 범위가 넓어집니다

플러그인이 할 줄 아는 일을 늘린다면, 아래 연결은 볼 수 있는 범위를 넓힙니다. 모두 선택이고, 연결하지 않아도 나머지는 그대로 동작합니다.

| 연결 | 붙이면 생기는 일 | 어디서 |
| 지라 · 컨플루언스

메일 · 캘린더 · 드라이브 | 내 이슈·문서·일정을 직접 읽고 씁니다.

“이번 주 한 일 주간보고로 정리해줘” · “세 명 다 되는 시간 찾아줘” 가 이 연결로 동작합니다 | 업무 도구 연결 (/env-setup) |
| 포털 MCP | 카탈로그와 템플릿을 직접 조회합니다.

“새 프로젝트 시작하고 싶은데” 에 만들 수 있는 종류를 바로 대조해 주고, 화면을 먼저 열지 않아도 진행됩니다 | 개발 환경 셋팅 (/dev-env-setup) |
| 크롬 브라우저 | 화면을 읽고, 누르고, 콘솔 오류를 그대로 봅니다.

“지금 열린 화면에서 뭐가 잘못됐는지 봐줘” 처럼 포털 작업을 대신 시킬 수 있습니다 | 개발 환경 셋팅 (/dev-env-setup) |
| Claude Design | 시안을 클라우드에 직접 만들고 고칩니다.

“화면 그려줘” · “시안 고치고 싶어” 가 여기까지 이어집니다 | 개발 환경 셋팅 (/dev-env-setup) |

그라파나를 연결하면 지표까지 직접 봅니다

“서비스 상태 봐줘”라고 물었을 때, 연결이 있으면 지표를 가져와 답합니다. 아직 없으면 어느 화면에서 무엇을 보면 되는지 알려 줍니다 — 어느 쪽이든 답은 받습니다.

/env-setup 과 /dev-env-setup 은 연결하는 명령이면서 확인하는 명령입니다. 이미 돼 있는 것은 건너뛰고, 끝나면 지금 무엇이 붙어 있는지를 이렇게 보여 줍니다.

/env-setup 업무 도구 연결 확인

실제로 호출해 보고 그 결과를 보여줍니다. 어느 계정으로 붙었는지, 캘린더는 어디까지 보이는지까지 나옵니다.

/dev-env-setup 개발 런타임과 도구

설치된 버전과 상태를 확인한 내용입니다.

05

## 막히면

플러그인은 보이는데 skill 이 0개예요. 오류 없이 이렇게 되는 경우가 있습니다. /plugin → Installed 에서 개수까지 확인하시고, 0이면 플랫폼개발팀으로 알려 주세요.

사내 저장소가 404 로 나와요. 조직 멤버인데도 404 라면 대개 토큰에 조직 SSO 승인이 없는 것입니다. 권한 문제가 아니라 1분이면 풀리니, 클로드에게 그대로 말하면 재승인을 진행합니다.

사용법을 외워야 하나요? 아닙니다. 각 플러그인이 자기 문서를 갖고 있어서 “지금 하려는 일에 어떤 걸 쓰면 좋을지 추천해줘” 라고 물으면 됩니다. 그래서 이 글에도 사용법을 옮겨 적지 않았습니다 — 물어보는 쪽이 항상 최신입니다.
