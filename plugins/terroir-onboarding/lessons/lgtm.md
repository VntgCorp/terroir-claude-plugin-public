# LGTM — 배포한 앱을 계속 지켜보는 법

Terroir에 올린 앱은 배포되는 순간부터 로그와 메트릭이 자동으로 쌓이고, 모든 데이터는 모니터링 전용 화면인 Grafana에서 봅니다. 이 글에서는 어떤 데이터가 저절로 모이고 무엇을 따로 켜야 하는지, 앱에 문제가 생기면 어떤 알림이 오는지를 설명합니다.

R&D실 플랫폼개발팀 읽는 시간 약 7분

한눈에 보기 — 로그와 운영 메트릭은 배포만 하면 수집기(Alloy)가 가져갑니다. 트레이스는 설정을 추가한 앱만 보내고, 같은 Alloy를 거쳐 Tempo에 쌓입니다. 쌓인 데이터는 Grafana에서 보고, 알림 규칙이 같은 데이터를 지켜보다가 이상이 생기면 우리 팀 Chat 스페이스으로 알립니다.

## 배포한 뒤에 무엇을 봐야 할까

앱을 배포했다고 일이 끝나지는 않습니다. 사용자가 늘면 메모리가 모자라고, 외부 API가 느려지면 응답이 밀리고, 새 버전에 들어간 버그는 특정 요청에서만 터집니다. 이런 일을 사용자보다 먼저 알아채려면 앱이 지금 어떤 상태인지 계속 볼 수 있어야 합니다. 이것을 관측(observability)이라고 부릅니다.

관측에는 보통 세 가지 데이터를 씁니다. 무슨 일이 있었는지는 로그가, 얼마나 나빠졌는지는 메트릭(CPU · 메모리 사용량, 재시작 횟수 등)이, 요청이 어디서 느려졌는지는 트레이스(요청 하나가 거쳐 간 경로와 구간별 소요 시간)가 알려 줍니다.

이 세 가지를 팀마다 직접 갖추려면 수집 도구, 저장소, 대시보드, 알림을 각각 설치하고 운영해야 합니다. 앱보다 관측 도구를 관리하는 데 시간이 더 드는 일도 흔합니다. Terroir는 이 구성을 미리 갖춰 두고, 모든 앱이 같은 구성을 함께 쓰게 했습니다.

## 어떤 도구를 골랐나

Terroir의 관측 도구는 모두 Grafana 생태계의 오픈소스입니다. 로그는 Loki, 화면은 Grafana, 트레이스는 Tempo, 메트릭은 Mimir가 맡고, 앞 글자를 따서 LGTM이라고 부릅니다. 로그와 메트릭을 모으는 수집기는 같은 생태계의 Alloy로 통일했습니다.

이 조합을 고른 이유는 세 가지입니다.

- 클라우드와 사내 서버에서 똑같이 씁니다. Terroir는 Google Cloud와 사내 서버(온프레미스)를 함께 운영합니다. 클라우드 전용 서비스를 쓰면 두 환경의 관측 방식이 갈라집니다.
- 한 화면에서 이어서 봅니다. 로그 · 메트릭 · 트레이스가 같은 Grafana 안에 있어서, 메트릭이 튄 시각의 로그를 바로 옆에서 찾을 수 있습니다.
- 수집기가 하나입니다. Alloy 하나로 로그와 메트릭을 모두 모으므로, 데이터 종류마다 에이전트를 따로 깔고 관리할 필요가 없습니다.

## 배포만 하면 쌓이는 것

Terroir의 모든 쿠버네티스 클러스터에는 수집기 Alloy가 설치돼 있습니다. 앱을 배포하면 Alloy가 그 앱을 알아서 찾아, 콘솔 로그와 컨테이너의 CPU · 메모리 · 재시작 횟수 같은 운영 메트릭을 가져갑니다. 앱 쪽에서 할 일은 없습니다.

로그는 앱이 콘솔(표준 출력)에 찍는 것만 수집합니다. 앱 안에서 파일로 로그를 쓰면 수집기가 볼 수 없으니, 로그는 콘솔로 내보내야 합니다.

수집된 모든 데이터에는 프로젝트 · 앱 · 워크로드(API 서버처럼 실제로 실행되는 단위) 이름이 자동으로 붙습니다. 수많은 앱의 데이터가 한 저장소에 섞여 있어도, 대시보드에서 내 앱만 골라 볼 수 있는 이유입니다.

저장 기간은 데이터 종류마다 다릅니다. 현재 설정 기준으로 로그는 14일, 메트릭은 90일, 트레이스는 24시간 동안 보관합니다.

## 트레이스는 한 번 설정하면 켜진다

로그와 운영 메트릭은 앱 바깥에서 보고 모을 수 있지만, 트레이스는 앱 안에서 만들어야 합니다. 요청이 어느 함수와 어느 DB 호출을 거쳐 몇 밀리초씩 걸렸는지는 앱만 알기 때문입니다. 그래서 트레이스는 앱마다 한 번 설정해야 켜집니다.

이 설정은 Claude Code 스킬이 대신 해 줍니다. Claude Code 에서 아래 순서로 실행합니다.

트레이스 켜기 Claude Code 에서

```
# 1. Terroir 개발 플러그인 설치 (처음 한 번)
/plugin install terroir-project-development@terroir-claude-plugin

# 2. 트레이스를 붙일 앱 레포에서 실행
/otel-instrument

# 명령 대신 말로 요청해도 같은 스킬이 동작합니다
이 서비스에 트레이스 붙여줘
```

- 스킬이 먼저 앱의 종류를 확인하고, 이 앱에 무엇이 필요한지 설명합니다.
- 의존성과 실행 옵션, 환경변수만 바꾸고 앱 코드는 고치지 않습니다. 바꾸기 전에 확인을 받습니다.
- 마지막에 트레이스가 실제로 Tempo에 들어오는지까지 확인합니다.

트레이스는 개발 환경과 운영 환경 모두에서 켤 수 있습니다. 이 자동 설정은 지금 Node(NestJS 포함) · Java · Python 앱을 지원합니다. 다른 언어도 OpenTelemetry 표준 방식으로 직접 연동할 수 있지만, 스킬이 대신 해 주는 절차는 아직 없습니다. 트레이스가 켜지면 요청 수 · 에러율 · 응답 시간 같은 네트워크 통계도 함께 볼 수 있습니다. 이 통계는 트레이스에서 계산하기 때문에, 트레이스를 켠 앱에만 나옵니다.

## Grafana에서 보기

대시보드를 따로 만들지 않아도 아래 네 가지가 기본으로 준비돼 있습니다. 포털에서 내 프로젝트를 열고 Grafana 버튼을 누르면 프로젝트 · 앱 · 워크로드 대시보드로 바로 이동하고, 「배포 진행 상황」은 포털에 버튼이 없어 Grafana 에서 직접 엽니다.

## 알림 — 고칠 수 있는 것만 보낸다

대시보드는 누군가 열어 봐야 쓸모가 있습니다. 그래서 Terroir는 앱에 문제가 생기면 팀의 Google Chat 스페이스으로 알림을 보냅니다. 방은 팀이 직접 만들고, 포털 프로젝트 화면의 「알림 채널 연결」에 방의 webhook 주소를 넣어 신청합니다. 플랫폼개발팀이 검토해 반영한 뒤부터 알림이 발송됩니다. 이 주소도 비밀값이라 005편에서 설명한 방식으로 봉인돼 저장됩니다.

어떤 알림을 보낼지는 하나의 기준으로 골랐습니다. 알림을 받은 개발자가 자기 코드 · 설정 · 배포로 상황을 바꿀 수 있는가. 서버 용량이나 노드 상태처럼 개발자가 손댈 수 없는 문제는 알려 봐야 할 수 있는 일이 없으므로 보내지 않습니다.

| 알림 | 언제 | 할 수 있는 일 | 등급 |
| 앱 상태 이상 | 배포 상태가 Degraded 또는 Missing 으로 15분 지속 | 배포 상태 확인, 이전 버전으로 되돌리기 | 긴급 |
| 컨테이너가 시작되지 못함 | 이미지나 설정 오류로 대기 상태가 15분 지속 | 이미지 태그, CI가 이미지를 올렸는지, 설정값 확인 | 주의 |
| 재시작 반복 | 뜨자마자 종료되기를 15분 동안 반복 | 로그 확인, 코드 수정 | 주의 |
| 요청을 받을 준비가 안 됨 | 준비 상태가 되지 않은 채 15분 지속 | 상태 확인(probe) 설정과 요청량 확인 | 주의 |
| 메모리가 한도에 가까움 | 한도의 85% 이상이 15분 동안 지속 | 종료되기 전에 메모리 한도 상향 | 주의 |
| 메모리 부족으로 강제 종료 | 최근 1시간 안에 한도를 넘어 종료됨 | 메모리 한도 상향 또는 사용량 축소 | 주의 |
| 에러 로그 급증 | 5분 동안 에러 로그 10건 이상 | 반복되는 에러 확인, 로그 레벨 조정 | 주의 |
| 하루 사이 재시작 반복 | 최근 24시간 동안 세 번 이상 재시작 | 메모리 한도 상향, 종료 직전 로그 확인 | 주의 |

긴급은 지금 앱이 뜨지 않거나 배포가 실패했다는 뜻이라 바로 확인해야 합니다. 주의는 당장 전면 장애로 보지는 않지만 앱의 실행이나 안정성에 문제가 있다는 뜻이라, 업무시간 안에 확인하면 됩니다.

메모리만 알림이 두 개인 이유가 있습니다. CPU는 한도를 넘어도 느려질 뿐이지만, 메모리는 한도를 넘는 순간 앱이 강제로 종료됩니다. 그래서 종료된 뒤에 알리는 것과 별도로, 종료되기 전에 한 번 더 알립니다.

## 아직 남은 한계

- 앱이 직접 만드는 메트릭은 아직 켤 수 없습니다. 주문 수나 결제 성공률처럼 앱이 계산해 내보내는 값은, 수집기 자체는 받을 수 있지만 포털에서 수집을 켜는 기능이 아직 없습니다.
- 트레이스는 24시간만 보관합니다. 며칠 전에 있었던 느린 요청을 트레이스로 추적할 수는 없습니다.
- 알림 규칙을 직접 조정할 수 없습니다. 기준값을 바꾸거나 특정 알림을 끄고 싶으면 알림 채널에서 요청해 주세요. 규칙은 프로젝트마다 따로 있어서, 한 프로젝트를 조정해도 다른 프로젝트에는 영향이 없습니다.

## 직접 써 보기

- Terroir 포털(terroir.vntgcorp.com)에서 내 프로젝트를 열고 Grafana 버튼을 누릅니다. 「워크로드 상세」 대시보드에서 로그와 메트릭을 확인합니다.
- 트레이스를 켜려면 Claude Code에 Terroir 개발 플러그인 terroir-project-development 를 설치합니다. 그다음 트레이스를 붙일 앱의 소스 저장소에서 "이 서비스에 트레이스 붙여줘"라고 요청하거나 /otel-instrument 를 실행합니다.
- 팀 알림을 받으려면 Google Chat 스페이스에서 webhook 주소를 발급하고, 포털 프로젝트 화면의 「알림 채널 연결」에 넣어 신청합니다. 플랫폼개발팀이 반영하면 알림이 오기 시작합니다.
