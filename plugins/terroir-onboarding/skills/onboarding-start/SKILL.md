# onboarding-start

Terroir 온보딩의 진입점. 이 문서가 온보딩 전체 흐름의 source of truth다. 각 단계의 세부 절차는 해당 단계 스킬이 소유한다.

```
직무 확인 질문 (답을 기억해 두고, 여기서 분기하지 않음)
        ↓
공통 환경 셋팅 진행 여부 질문 (연결하기 / 건너뛰기)
        ↓ 연결하기 → env-setup   /   건너뛰기 → 바로 다음 단계
   §1의 답으로 분기 (직무를 다시 묻지 않음)
   ├─ 프로덕트 관련 직군 (개발·기획·디자인·PM 등)
   │    ├─ GitHub 계정 있음 → github-connect (조직 접근 확인, 불가면 org-access-request로 분기)
   │    └─ 계정 없음       → org-access-request
   └─ 비 프로덕트 직군 → §3 일반 업무 활용 안내
        ↓
   §4 공통 종료 출력 (제공 기능 안내 + "무엇을 도와드릴까요")
```

## 진행 절차

### 1. 직무 확인

온보딩 시작 직후, 먼저 AskUserQuestion으로 직무를 묻는다. 사용자가 항상 답을 아는 질문이라 첫 단계로 부담이 없고, 이어지는 §2의 화법을 직무에 맞출 수 있다.

> 어떤 직무를 맡고 계신가요?
> 1. 프로덕트 관련 직군 — 개발, 기획, 디자인, PM 등 프로덕트를 만드는 일
> 2. 비 프로덕트 직군 — 그 외 (경영지원, 영업, 인사 등)

**여기서 바로 분기하지 않는다.** 답을 기억해 두고 §2(공통 환경 셋팅)를 먼저 진행한 뒤, §2 끝에서 이 답으로 분기한다.

### 2. 공통 환경 셋팅 (1회만)

직무와 무관하게 모두에게 필요한 도구 연결이다. AskUserQuestion으로 진행 여부를 묻되, §1에서 받은 직무에 맞춰 화법을 조정한다.

> 업무 도구 연결(지라·컨플루언스 / 이메일·캘린더·드라이브)을 지금 진행할까요?
> - **연결하기** — 도구 연결 상태를 점검하고 미연결 항목을 연결
> - **건너뛰기** — 나중에 `/env-setup`으로 연결하고, 지금은 다음 단계로

- **비 프로덕트 직군**에게는 이 연결이 온보딩의 핵심이므로 연결하기를 권한다.
- **프로덕트 관련 직군**에게는 뒤에 GitHub 연결이 이어지므로 건너뛰어도 지장 없다고 덧붙인다.

선택에 따른 처리는 직무와 무관하게 같다.

- **연결하기** → `env-setup` 스킬을 실행한다.
- **건너뛰기** → env-setup을 호출하지 않는다. 건너뛴 사실은 §4 종료 출력에서 "도구 연결은 `/env-setup`으로 언제든 진행할 수 있다"로 한 줄 안내한다.

이후 어느 경로로 가든 이 단계를 다시 진행하지 않는다.

#### 2-1. 단계 종료 후 직무별 분기

env-setup은 사용자가 `/mcp`를 입력하기를 기다리며 턴을 여러 번 끊는다. 그 뒤에도 **직무를 다시 묻지 않는다** — §1의 답을 그대로 쓰되, 분기 근거를 한 문장으로 밝히고 넘어간다 (예: "프로덕트 직군이시니 GitHub 연결로 이어가겠습니다").

- **프로덕트 관련 직군** → GitHub 계정 보유 여부를 묻는다. VNTG 조직 소속 여부는 사용자에게 묻지 않는다 — github-connect의 접근 확인이 판별한다. GitHub 관련 내용이 익숙하지 않은 사용자를 위해 질문에 사내 GitHub 가이드 문서를 함께 안내한다: https://vntg.atlassian.net/wiki/external/NWEwMzYzYzQ1M2JhNDI1ODk1ZTEzN2IwYWI4NjNlOWI
  - 계정 있음 (조직 소속 여부는 몰라도 됨) → `github-connect` 스킬 실행 (계정 연결 → Git 연결 → private 플러그인 접근 확인·설치, 접근 불가면 org-access-request로 자동 분기)
  - GitHub 계정 없음 → `org-access-request` 스킬 실행 (가입 지원·접근 요청)
- **비 프로덕트 직군** → §3으로.

### 3. 비 프로덕트 직군 경로 (End point 정의)

비 프로덕트 직군의 온보딩 End point는 **"공통 환경 셋팅 완료 + 일반 업무 활용 안내"**다. GitHub·프로덕트 도구 연결은 진행하지 않는다.

아래를 안내한 뒤 §4를 실행한다.

> 업무 도구 연결이 끝났습니다. 이제 Claude와 함께 이런 일을 할 수 있습니다.
>
> - 문서 작성·요약 — 컨플루언스 문서 초안, 회의록 정리, 보고서 다듬기
> - 메일 — 받은 메일 검색·요약, 답장 초안 작성
> - 일정 — 캘린더 조회, 회의 시간 조율
> - 자료 찾기 — 구글 드라이브·컨플루언스에서 자료 검색
> - 지라 — 이슈 조회·작성·정리

### 4. 공통 종료 출력

모든 경로의 종착점. 아래 순서로 출력하고 "무엇을 도와드릴까요?"로 마친다. 새 세션에서 "내가 무엇을 할 수 있지?" 류의 질문을 받았을 때도 앞 단계 없이 이 섹션만 실행한다.

1. **설치된 플러그인 안내 (동적 조회)**: 설치된 플러그인 목록을 조회해(`claude plugin list` — 실패 시 현재 세션에 로드된 플러그인·스킬로 갈음) terroir 마켓플레이스의 플러그인만 골라 아래 표 형식으로 안내한다. "하는 일"은 각 플러그인의 description을 사용자 눈높이로 한 줄 요약하고, "시작 방법"은 그 플러그인 스킬의 트리거 예시(when_to_use)에서 대표 문구나 커맨드 1개를 골라 적는다. **플러그인 목록·설명·트리거를 이 문서에 적어두지 않는다 — 조회 결과가 항상 진실이다.**

   | 플러그인 | 하는 일 | 시작 방법 |
   | --- | --- | --- |
   | (조회된 플러그인 이름) | (description 한 줄 요약) | (대표 트리거 문구 또는 /커맨드) |
2. **일반 업무 지원 안내 (모든 직군 공통)**: 지라·컨플루언스·메일·캘린더·드라이브와 연결된 일반 업무 지원(문서 작성·요약, 검색, 일정 관리)을 안내한다.
3. "무엇을 도와드릴까요?"로 마친다.

private 플러그인이 설치되지 않은 사용자(비 프로덕트 직군 등)는 1의 목록이 자연스럽게 비므로 2만 안내한다 — 별도 분기를 두지 않는다.

## 주의

- 이 스킬과 플러그인 문서에는 사내 URL·사내 이메일·private 플러그인의 이름 목록을 적지 않는다. 사용자 안내에 필요한 플러그인 목록은 §4처럼 런타임 조회로 얻는다.
