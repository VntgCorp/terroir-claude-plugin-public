# onboarding-start

Terroir 온보딩의 진입점. 이 문서가 온보딩 전체 흐름의 source of truth다. 각 단계의 세부 절차는 해당 단계 스킬이 소유한다.

```
공통 환경 셋팅 진행 여부 질문 (연결하기 / 건너뛰기)
        ↓ 연결하기 → env-setup   /   건너뛰기 → 바로 다음 단계
   직무 확인 질문
        ↓
   ├─ 프로덕트 관련 직군 (개발·기획·디자인·PM 등)
   │    ├─ GitHub 계정 있음 → github-connect (조직 접근 확인, 불가면 org-access-request로 분기)
   │    └─ 계정 없음       → org-access-request
   └─ 비 프로덕트 직군 → §3 일반 업무 활용 안내
        ↓
   §4 공통 종료 출력 (제공 기능 안내 + "무엇을 도와드릴까요")
```

## 진행 절차

### 1. 공통 환경 셋팅 (직무 분기 전, 1회만)

온보딩 시작 직후, 먼저 AskUserQuestion으로 공통 환경 셋팅 진행 여부를 묻는다.

> 업무 도구 연결(지라·컨플루언스 / 이메일·캘린더·드라이브)을 지금 진행할까요?
> - **연결하기** — 도구 연결 상태를 점검하고 미연결 항목을 연결
> - **건너뛰기** — 나중에 `/env-setup`으로 연결하고, 지금은 다음 단계로

- **연결하기** → `env-setup` 스킬을 실행한다. 직무와 무관하게 모두에게 필요한 도구 연결을 안내·점검한다.
- **건너뛰기** → env-setup을 호출하지 않고 §2로 바로 넘어간다. 건너뛴 사실은 §4 종료 출력에서 "도구 연결은 `/env-setup`으로 언제든 진행할 수 있다"로 한 줄 안내한다.

이후 어느 경로로 가든 이 단계를 다시 진행하지 않는다.

### 2. 직무 확인

사용자에게 묻는다.

> 어떤 직무를 맡고 계신가요?
> 1. 프로덕트 관련 직군 — 개발, 기획, 디자인, PM 등 프로덕트를 만드는 일
> 2. 비 프로덕트 직군 — 그 외 (경영지원, 영업, 인사 등)

- **프로덕트 관련 직군** → GitHub 계정(개인 계정) 보유 여부를 묻는다. VNTG 조직 소속 여부는 사용자에게 묻지 않는다 — github-connect의 접근 확인이 판별한다.
  - 계정 있음 (조직 소속 여부는 몰라도 됨) → `github-connect` 스킬 실행 (계정 연결 → Git 연결 → private 플러그인 접근 확인·설치, 접근 불가면 org-access-request로 자동 분기)
  - GitHub 계정 없음 → `org-access-request` 스킬 실행 (가입 지원·접근 요청)
- **비 프로덕트 직군** → §3으로.

### 3. 비 프로덕트 직군 경로 (End point 정의)

비 프로덕트 직군의 온보딩 End point는 **"공통 환경 셋팅 완료 + 일반 업무 활용 안내"**다. GitHub·프로덕트 도구 연결은 진행하지 않는다.

아래를 안내한 뒤 §4를 실행한다.

> 업무 도구 연결이 끝났습니다. 이제 Claude와 함께 이런 일을 할 수 있습니다.
>
> - 문서 작성·요약 — 컨플루언스 문서 초안, 회의록 정리, 보고서 다듬기
> - 메일 — 받은 메일 검색·요약, 답장 초안 작성
> - 일정 — 캘린더 조회, 회의 시간 조율
> - 자료 찾기 — 구글 드라이브·컨플루언스에서 자료 검색
> - 지라 — 이슈 조회·작성·정리

### 4. 공통 종료 출력

모든 경로의 종착점. 아래 제공 기능 안내를 출력하고 "무엇을 도와드릴까요?"로 마친다. 새 세션에서 "내가 무엇을 할 수 있지?" 류의 질문을 받았을 때도 앞 단계 없이 이 섹션만 실행한다.

> Terroir와 함께 이런 일을 할 수 있습니다.
>
> **개발**
> - 요구사항 구체화부터 PRD·기술 설계·구현 계획·개발·코드 리뷰·QA까지 이어지는 스펙 기반 개발 워크플로우
> - 커밋 메시지·PR 생성 등 개발 표준 자동화
> - 서비스에 분산 트레이싱을 붙이는 관측성 계측, 컨테이너화 지원
>
> **기획·디자인**
> - 기획 문서(PRD·SPEC)에서 화면 명세를 뽑아 디자인 시안을 만들고 수정하는 워크플로우
> - 기존 코드에서 디자인 시스템을 추출·문서화
>
> **기타 (모든 직군 공통)**
> - 지라·컨플루언스·메일·캘린더·드라이브와 연결된 일반 업무 지원 — 문서 작성, 검색, 일정 관리
> - 팀 지식을 저장하고 근거와 함께 질의
>
> 무엇을 도와드릴까요?

개발·기획·디자인 기능은 private 플러그인 설치(프로덕트 관련 직군 온보딩 완료) 후 사용할 수 있다. 비 프로덕트 직군 사용자에게는 "기타" 항목이 현재 사용 가능한 범위임을 함께 알린다.

## 주의

- 이 스킬과 플러그인 문서에는 사내 URL·사내 이메일·private 플러그인의 이름 목록을 적지 않는다. 기능은 서술로만 안내한다.
