# work-map

업무 지도를 만들고, 값을 저장하고, 고친다. **이 스킬은 받은 값을 지도에 적는 일만 한다.** 값이 어디서 왔는지(사용자가 말했는지, 다른 스킬이 도구로 찾았는지)는 따지지 않는다. 도구로 후보를 찾는 일은 그 도구를 다루는 쪽이 맡고, 고른 값만 이 스킬에 넘긴다.

지도는 **어디에 무엇이 있는지**(주소·ID·사람)를 담는다. 일하는 방식·판단·피드백은 담지 않는다 — 그것은 Claude Code 의 메모리가 맡는다. 같은 내용이 두 곳에 쌓이지 않게 이 경계를 지킨다.

세션이 시작될 때 이 플러그인의 훅이 지도의 칸 제목과 `> 언제 읽나:` 줄만 세션에 넣는다. 값은 Claude 가 그 칸에 해당하는 일을 할 때 파일을 열어 읽는다. 그래서 **칸 형식을 지키는 것이 이 스킬의 계약이다** — 형식이 깨지면 다음 세션부터 그 칸이 목차에서 사라지거나, 언제 읽을지 없이 제목만 뜬다.

## 0. 경로와 저장 (모든 절차 공통 — 먼저)

- **템플릿:** 이 스킬이 로드될 때 맨 위에 표시되는 `Base directory for this skill: <절대경로>` 의 `<절대경로>/template.md`. 환경변수(`$CLAUDE_PLUGIN_ROOT`·`$CLAUDE_SKILL_DIR`)는 bash 블록에 주입되지 않으므로 쓰지 않는다.
- **지도 파일:** `CLAUDE_CONFIG_DIR` 가 있으면 `$CLAUDE_CONFIG_DIR/terroir/work-map.md`, 없으면 `~/.claude/terroir/work-map.md`.

```bash
MAP="${CLAUDE_CONFIG_DIR:-$HOME/.claude}/terroir/work-map.md"
[ -f "$MAP" ] && echo "EXISTS $MAP" || echo "MISSING $MAP"
```

업무 지도는 사용자마다 하나만 둔다. 레포나 다른 폴더에 사본이 생기면 어느 것이 맞는지 갈리므로, 사용자 폴더의 이 파일 하나만 쓰고 다른 곳에 복사하지 않는다. 이메일·동료 ID 가 들어 있어 커밋하지도 않는다.

**지도가 없을 때 처음 쓰는 경우**에는 템플릿을 복사하고 권한을 본인만 읽게 둔 뒤 쓴다. `<BASE_DIR>` 는 위의 절대경로로 바꿔 넣는다. Windows 에서 `chmod` 가 효과가 없어도 실패로 보지 않는다.

```bash
mkdir -p "$(dirname "$MAP")" && cp "<BASE_DIR>/template.md" "$MAP" && chmod 600 "$MAP" 2>/dev/null; echo done
```

**저장 승인:** 기본 권한 모드(`default`)에서는 `~/.claude` 아래 파일을 쓸 때마다 승인 창이 뜨고, 허용 규칙으로도 생략되지 않는다(`auto` 모드에서는 뜨지 않는다). 이 세션에서 지도에 처음 쓰기 직전에 아래 한 줄을 알린다. 창이 뜰지 미리 알 수 없으므로 조건형으로 쓴다. 부른 쪽이 이 세션에서 같은 안내를 이미 냈으면 다시 내지 않는다. `{지도 폴더}` 는 `$MAP` 의 폴더로 바꿔 쓴다(`CLAUDE_CONFIG_DIR` 를 쓰는 사용자는 `~/.claude` 가 아니다).

> 업무 지도(work-map)는 사용자 폴더(`{지도 폴더}`)에 저장됩니다. 저장 승인 창이 뜨면 허용해 주세요.

**한 번에 쓴다.** 저장할 값이 여럿이면 다 모은 뒤 한 번에 쓴다. 칸마다 쓰면 기본 권한 모드에서 승인 창이 그만큼 뜬다.

사용자가 승인을 거절하면 **그 저장 한 번만** 건너뛴다. 거절했다는 사실을 기억해 두지 않는다 — 같은 세션에서 다음에 저장할 일이 생기면 평소처럼 시도한다. 사용자가 직접 불렀으면 받은 값을 화면에 한 번 보여 주고 "지금은 저장하지 않았습니다. 나중에 `/work-map` 으로 저장할 수 있습니다."라고 알린다. 다른 스킬이 불렀으면 아무것도 더하지 않고 부른 쪽으로 돌아간다.

## 1. 무엇을 할지 가르기

부른 쪽이 누구인지가 아니라 **받은 요청이 무엇인지**로 가른다.

| 요청 | 할 일 |
| --- | --- |
| 칸과 값이 정해진 저장 요청(예: 프로필 네 값, 고른 지라 프로젝트) | §2 값 저장 |
| 범위 없는 등록 요청("등록해줘", "지도 만들어줘") | §3 처음 등록 |
| 특정 칸의 값을 고치라는 요청, 또는 지도 값이 실제와 다르다는 것을 알게 된 경우 | §4 칸 고치기 — **그 칸만** 다룬다 |
| 지도에 없는 종류를 넣어 달라는 요청("이것도 지도에 넣어줘") | §4-1 칸 더하기 |

등록 요청과 함께 저장할 값(예: 프로필)도 넘겨받았으면, 그 값은 §3 에서 다시 묻지 않고 §3 의 다른 값과 함께 한 번에 저장한다.

## 2. 값 저장

받은 값을 해당 칸에 적는다.

- 표 칸이면 행으로 더한다. 같은 대상(같은 키·주소·이메일)이 이미 있으면 새 행을 만들지 않고 그 행을 고친다.
- 프로필 칸이면 네 줄(이메일 · 자신을 부를 이름 · 직무 분류 · 직무) 중 받은 줄만 채우거나 바꾼다.
- "확인" 열: 부른 쪽이 도구로 확인한 값이라고 하면 `조회됨`, 그 밖에는 `직접 입력`. 검증은 표시만 하고 막지 않는다.
- 이메일을 적을 때는 무엇을 적는지 한 줄로 보여 준다(개인 정보라 사용자가 한 번 보고 지나가야 한다).
- 저장한 뒤 무엇을 적었는지 한 줄로 알린다.

## 3. 처음 등록

한꺼번에 다 받지 않는다. 저장할 칸을 먼저 고르게 하고, 고른 칸만 묻는다.

1. 아래 목록을 보여 주고 "어떤 것을 저장할까요? 번호로 답해 주세요(여럿이면 쉼표로). 나중에 필요할 때 더해도 됩니다."라고 묻고 턴을 끝낸다. 이미 값이 있는 칸은 이름 뒤에 "(저장됨)"을 붙인다.

   > 1. 지라·컨플루언스 프로젝트
   > 2. 자주 쓰는 채널
   > 3. 자주 대화하는 사람
   > 4. GitHub 프로젝트
   > 5. 드라이브 주소
   > 6. 규칙 위치

2. 고른 칸마다 한 턴씩 값을 받는다. 첫 칸을 물을 때 "칸을 넘기려면 \"건너뛰기\", 여기서 끝내려면 \"그만\"이라고 답해 주세요."를 한 번 붙인다.

   | 칸 | 받는 방법 |
   | --- | --- |
   | 지라·컨플루언스 프로젝트 | 프로젝트·스페이스 주소를 붙여 넣게 하고 주소에서 키를 뽑아 적는다 |
   | 자주 쓰는 채널 | 채널 웹 주소와 용도를 받고, 주소의 방 ID 부분(예: 구글챗 `…/room/<ID>` 의 `<ID>`)을 적는다 |
   | 자주 대화하는 사람 | 호칭·이름·이메일을 받는다. **호칭은 항상 받는다** — 표시 이름과 실제로 부르는 이름이 다른 경우가 흔하고, 그것을 맞춰 두는 것이 이 칸의 목적이다. 채팅 ID 는 비워 둬도 된다 |
   | GitHub 프로젝트 | 레포 주소와 역할을 받는다 |
   | 드라이브 주소 | 폴더·문서 주소를 받는다 |
   | 규칙 위치 | 문서 주소나 레포 경로를 받는다 |

3. "건너뛰기"면 그 칸을 비워 둔다. "그만"이면 남은 칸을 묻지 않는다.
4. 받은 값을 §0 대로 **한 번에** 저장하고 §5 로 마무리한다.

## 4. 칸 고치기

1. 지도 파일을 읽고 해당 칸을 찾는다.
2. 그 칸의 값만 고친다. 칸 제목과 `> 언제 읽나:` 줄은 사용자가 바꾸라고 할 때만 바꾼다.
3. 무엇을 바꿨는지 한 줄로 알린다.

### 4-1. 칸 더하기

사용자가 지도에 없는 종류를 넣어 달라고 하면 새 칸을 만든다.

1. 칸 제목을 사용자가 쓴 말로 정한다.
2. **"언제 읽나" 한 줄을 반드시 적는다.** 사용자가 말하지 않았으면 그 칸이 쓰일 일을 한 줄로 정해 적고, 무엇으로 적었는지 알린다 — 이 줄이 없으면 세션 목차에 제목만 뜨고 언제 열어야 하는지 모른다.
3. 파일 맨 끝에 아래 형식으로 붙인다.

   ```markdown
   ## <칸 제목>
   > 언제 읽나: <이 칸이 쓰이는 일>

   <값 — 목록 또는 표>
   ```

4. 다음 세션부터 목차에 나타난다고 알린다.

**넣지 않는 것:** 일하는 방식·말투 선호·피드백(예: "PR 본문은 짧게")은 칸으로 만들지 않는다. 이런 내용은 지도가 아니라 메모리에 남긴다고 한 줄로 알리고, 원하면 메모리에 남기도록 안내한다.

## 5. 마무리 출력

§3 처음 등록을 마치면 아래를 알린다.

> 업무 지도(work-map)를 저장했습니다: `<지도 경로>`
> 다음 세션부터 Claude 가 이 지도를 먼저 보고 일합니다. 고치거나 더할 것이 생기면 "지도 고쳐줘" 또는 "이것도 지도에 넣어줘"라고 말씀해 주세요.

채운 칸과 비운 칸을 한 줄씩 덧붙인다(예: "채움: 프로필, 지라·컨플루언스 프로젝트 / 비움: 자주 쓰는 채널"). 값 자체는 다시 나열하지 않는다.

## 주의

- 이 스킬과 템플릿에는 사내 URL·사내 이메일·private 플러그인 이름을 적지 않는다. 예시는 형식만 보인다.
- 지도 파일의 칸 형식(`## 제목` 다음 줄 `> 언제 읽나: …`)을 바꾸지 않는다. 세션 시작 훅이 이 형식을 읽는다.
