# work-map

사용자별 업무 지도를 만들고 고친다. 지도는 **어디에 무엇이 있는지**(주소·ID·사람)를 담는다. 일하는 방식·판단·피드백은 담지 않는다 — 그것은 Claude Code 의 메모리가 맡는다. 같은 내용이 두 곳에 쌓이지 않게 이 경계를 지킨다.

지도를 읽는 쪽은 이 플러그인의 세션 시작 훅(`hooks/session-start.sh`)이다. 훅은 칸 제목과 `> 언제 읽나:` 줄만 세션에 넣고, 값은 Claude 가 그 칸에 해당하는 일을 할 때 파일을 열어 읽는다. 그래서 **칸 형식을 지키는 것이 이 스킬의 계약이다** — 형식이 깨지면 다음 세션부터 그 칸이 목차에서 사라진다.

## 0. 경로 잡기 (모든 절차 공통 — 먼저)

- **템플릿:** 이 스킬이 로드될 때 맨 위에 표시되는 `Base directory for this skill: <절대경로>` 의 `<절대경로>/template.md`. 환경변수(`$CLAUDE_PLUGIN_ROOT`·`$CLAUDE_SKILL_DIR`)는 bash 블록에 주입되지 않으므로 쓰지 않는다.
- **지도 파일:** `CLAUDE_CONFIG_DIR` 가 있으면 `$CLAUDE_CONFIG_DIR/terroir/work-map.md`, 없으면 `~/.claude/terroir/work-map.md`.

```bash
MAP="${CLAUDE_CONFIG_DIR:-$HOME/.claude}/terroir/work-map.md"
[ -f "$MAP" ] && echo "EXISTS $MAP" || echo "MISSING $MAP"
```

지도 파일은 사용자 폴더에만 둔다. **현재 작업 폴더(레포)에 복사하거나 커밋하지 않는다** — 이메일·동료 ID 가 들어 있다.

**저장 승인:** Claude Code 는 `~/.claude` 아래 파일 쓰기를 민감한 파일로 보고, 허용 규칙과 무관하게 쓸 때마다 사용자 승인을 받는다. 이 세션에서 지도에 처음 쓰기 직전에 아래 한 줄을 알린다. `{지도 폴더}` 는 위에서 구한 `$MAP` 의 폴더로 바꿔 쓴다(`CLAUDE_CONFIG_DIR` 를 쓰는 사용자는 `~/.claude` 가 아니다).

> 업무 지도는 사용자 폴더(`{지도 폴더}`)에 있어 저장할 때 승인 창이 뜹니다. 허용해 주세요.

사용자가 거절하면 다시 시도하지 않는다. 그다음은 누가 불렀는지로 갈린다.

- **사용자가 직접 불렀으면** — 모은 값을 화면에 한 번 보여 주고 "나중에 `/work-map` 으로 저장할 수 있습니다"라고 알린 뒤 이 스킬을 끝낸다.
- **다른 스킬(`onboarding`·`env-setup`)이 불렀으면** — 한 줄도 더하지 않고 곧바로 부른 스킬의 다음 단계로 돌아간다. 부른 쪽의 흐름을 멈추지 않는다.

## 1. 무엇을 할지 가르기

| 들어온 경우 | 할 일 |
| --- | --- |
| `MISSING` 이고 사용자가 등록·만들기를 요청 | §2 처음 만들기 |
| `onboarding` 이 프로파일 값을 넘김 | §5 프로파일 저장만 |
| `env-setup` 이 연결한 도구를 넘김 | §6-1 조회 대기 적기만 |
| 지도에 `## 조회 대기` 칸이 있고 사용자가 조회에 동의 | §6-2 조회 대기 처리 |
| 지도에 `## 조회 대기` 칸이 있고 사용자가 조회를 거절 | `## 조회 대기` 칸만 통째로 지우고 끝낸다. 다른 칸은 건드리지 않는다 |
| `EXISTS` 이고 특정 칸을 고치거나 값을 더하라는 요청 | §4 칸 고치기 — **그 칸만** 다룬다. 다른 칸을 다시 묻지 않는다 |
| `EXISTS` 이고 새 칸을 더하라는 요청("이것도 지도에 넣어줘") | §4-1 칸 더하기 |
| `EXISTS` 이고 "등록해줘"처럼 범위 없는 요청 | 비어 있는 칸만 §3 순서로 채운다. 채워진 칸은 건너뛴다 |

## 2. 처음 만들기

1. 템플릿을 지도 경로로 복사하고 권한을 본인만 읽게 둔다.

   ```bash
   mkdir -p "$(dirname "$MAP")" && cp "<BASE_DIR>/template.md" "$MAP" && chmod 600 "$MAP" 2>/dev/null; echo done
   ```

   `<BASE_DIR>` 는 §0 의 절대경로로 바꿔 넣는다. Windows 에서 `chmod` 가 효과가 없어도 실패로 보지 않는다.
2. 프로파일 칸이 비어 있으면 §5 로 먼저 채운다.
3. 나머지 칸을 §3 순서대로 하나씩 채운다.
4. 끝나면 §7 로 마무리한다.

시작할 때 아래 한 줄을 먼저 알린다 — 칸이 여섯 개라 사용자가 끝을 알 수 있어야 한다.

> 자주 쓰는 곳을 칸마다 하나씩 여쭙겠습니다. 어느 칸이든 "건너뛰기", 도중에 "그만"이라고 하시면 거기까지 저장합니다.

## 3. 칸별 값 모으기

칸마다 **한 턴**을 쓴다. 조회할 수 있으면 후보를 먼저 찾아 번호 목록으로 보여 주고, 사용자가 고른 것만 적는다. 목록 전체를 적지 않는다.

| 칸 | 조회로 후보 찾기 | 조회가 안 될 때 |
| --- | --- | --- |
| 지라·컨플루언스 프로젝트 | 지라·컨플루언스 커넥터(Atlassian)로 사용자가 볼 수 있는 지라 프로젝트와 컨플루언스 스페이스 목록 | 프로젝트·스페이스 주소를 붙여 넣게 하고 주소에서 키를 뽑아 적는다 |
| 자주 쓰는 채널 | 이 플러그인의 커넥터에는 채팅이 없다 | 채널 웹 주소를 붙여 넣게 하고 주소의 방 ID 부분(예: 구글챗 `…/room/<ID>` 의 `<ID>`)을 적는다 |
| 자주 대화하는 사람 | 지라 사용자 검색(이름 → 지라 ID), 메일 커넥터에서 최근에 주고받은 상대(이름·이메일) | 이름·이메일을 직접 받는다 |
| 깃헙 프로젝트 | `gh auth status` 가 로그인 상태면 `gh api "user/repos?sort=pushed&per_page=30" --jq '.[].full_name'` 로 최근에 푸시한 리포를 찾는다. 조직 리포를 더 보려면 `gh api user/orgs --jq '.[].login'` 로 조직을 보여 주고 고른 조직에 `gh repo list <조직> --limit 30` | 리포 주소를 받는다 |
| 드라이브 주소 | 드라이브 커넥터로 공유 드라이브·최근 폴더 | 폴더 주소를 받는다 |
| 규칙 위치 | 없다 | 문서 주소나 레포 경로를 받는다 |

- 커넥터가 세션에 없거나 조회가 실패하면 **그 칸만** 직접 입력으로 넘긴다. 실패를 이유로 등록 전체를 멈추지 않는다.
- **호칭은 항상 직접 받는다.** 지라·메일의 표시 이름과 실제로 부르는 이름이 다른 경우가 흔하고, 그것을 맞춰 두는 것이 이 칸의 목적이다.
- **채팅 ID 는 비워 둬도 된다.** 웹 주소에 드러나지 않아 얻기 어렵다. 멘션이 필요해질 때 채운다.
- 후보가 4개 이하면 AskUserQuestion(복수 선택)으로, 5개 이상이면 번호 목록으로 출력하고 "번호로 답해 주세요(여럿이면 쉼표로)"라고 묻고 턴을 끝낸다.
- 각 칸의 "확인" 열: 조회로 확인한 값은 `조회됨`, 사용자가 넣은 값은 `직접 입력`. 검증은 표시만 하고 막지 않는다.
- 이메일은 지도에 적기 전에 무엇을 적는지 한 줄로 보여 준다(개인 정보라 사용자가 한 번 보고 지나가야 한다).

## 4. 칸 고치기

1. 지도 파일을 읽고 요청한 칸을 찾는다.
2. 그 칸의 값만 고친다. 칸 제목과 `> 언제 읽나:` 줄은 사용자가 바꾸라고 할 때만 바꾼다.
3. 무엇을 바꿨는지 한 줄로 알린다.

세션 중 Claude 가 지도 값이 실제와 다르다는 것을 알게 된 경우(예: 지라 ID 가 틀려 조회가 실패)도 이 절차로 그 값만 고친다.

### 4-1. 칸 더하기

사용자가 지도에 없는 종류를 넣어 달라고 하면 새 칸을 만든다.

1. 칸 제목을 사용자가 쓴 말로 정한다.
2. **"언제 읽나" 한 줄을 반드시 적는다.** 사용자가 말하지 않았으면 그 칸이 쓰일 일을 한 줄로 정해 적고, 무엇으로 적었는지 알린다 — 이 줄이 없으면 세션 목차에 제목만 뜨고 언제 열어야 하는지 모른다.
3. 파일 맨 끝(`## 조회 대기` 칸이 있으면 그 앞)에 아래 형식으로 붙인다.

   ```markdown
   ## <칸 제목>
   > 언제 읽나: <이 칸이 쓰이는 일>

   <값 — 목록 또는 표>
   ```

4. 다음 세션부터 목차에 나타난다고 알린다.

**넣지 않는 것:** 일하는 방식·말투 선호·피드백("PR 본문은 짧게" 같은 것)은 칸으로 만들지 않는다. 이것은 지도가 아니라 메모리의 몫이라고 한 줄로 알리고, 원하면 메모리에 남기도록 안내한다.

## 5. 프로파일 저장

`onboarding` 이 넘긴 값(또는 §2 에서 모은 값)으로 `## 프로파일` 칸의 네 줄만 채운다.

- 이메일 · 자신을 부를 이름 · 직무 분류(프로덕트 관련 직군 / 비 프로덕트 직군) · 직무
- 지도 파일이 없으면 §2 의 1단계로 템플릿을 먼저 복사한 뒤 프로파일만 채운다. 나머지 칸은 비워 둔다.
- 프로파일 칸이 이미 채워져 있으면 넘겨받은 값으로 바꾸고, 바뀐 줄을 한 줄로 알린다.

값을 모으는 방법(`onboarding` 이 없이 여기서 모을 때):

```bash
claude auth status 2>/dev/null
grep -o '"displayName": *"[^"]*"' "${CLAUDE_CONFIG_DIR:-$HOME}/.claude.json" 2>/dev/null | head -1
```

- `claude auth status` 의 `email` 이 있으면 그것을 이메일로 쓴다. 없으면(claude.ai 로그인이 아니면) 직접 받는다.
- `displayName` 은 claude.ai 에 적어 둔 "Claude 가 부를 이름"이다. 있으면 "채팅이나 메일에서 본인을 **{displayName}**(으)로 쓸까요, 다른 이름을 쓸까요?"의 기본 선택지로 쓴다. 없으면 이름을 직접 받는다. 이 파일은 공개 형식이 아니라 값이 안 나올 수 있다 — 안 나오면 묻는 쪽으로 간다.

## 6. 조회 대기

방금 연결한 커넥터는 **다음 세션부터** 도구가 보인다. 그래서 연결한 세션에서는 조회하지 않고 표시만 해 두었다가 다음 세션에서 조회한다.

### 6-1. 조회 대기 적기

`env-setup` 이 이번에 연결한 커넥터 이름을 넘기면, 지도 맨 끝에 아래 칸을 만들거나 기존 칸에 줄을 더한다. 지도 파일이 없으면 §2 의 1단계로 템플릿을 먼저 복사한다.

```markdown
## 조회 대기
> 언제 읽나: 세션 시작 훅이 알린다 — 아래 도구로 지도 후보를 한 번 조회할지 묻는다

- 지라·컨플루언스 (YYYY-MM-DD 연결)
```

이 칸은 목차가 아니라 신호다. 훅은 이 칸을 목차에 넣지 않고 "조회할 차례"라는 안내로 바꿔 넣는다.

### 6-2. 조회 대기 처리

1. 칸에 적힌 커넥터가 이제 세션에 보이는지 확인한다.
2. 보이는 커넥터가 채울 수 있는 칸만 §3 방식으로 후보를 보여 준다.
   - 지라·컨플루언스 → 지라·컨플루언스 프로젝트, 자주 대화하는 사람(지라 ID)
   - 메일 → 자주 대화하는 사람(이메일)
   - 드라이브 → 드라이브 주소
   - 캘린더 → 기본 칸에 캘린더가 없다. 팀 캘린더를 지도에 둘지 묻고, 원하면 §4-1 로 "캘린더" 칸을 더한다
3. 처리가 끝나면 `## 조회 대기` 칸을 통째로 지운다. 후보를 하나도 고르지 않았어도 지운다 — **두 번 묻지 않는다.**
4. 적혀 있는데 이 세션에도 보이지 않는 커넥터가 있으면 그것도 함께 지우고 한 줄로 알린다 — "{커넥터}는 아직 연결이 확인되지 않아 조회하지 않았습니다. 연결한 뒤 `/work-map` 으로 채울 수 있습니다." 남겨 두면 연결될 때까지 매 세션 같은 질문이 반복된다.

## 7. 마무리 출력

저장한 뒤 아래를 알린다.

> 업무 지도를 저장했습니다: `<지도 경로>`
> 다음 세션부터 Claude 가 이 지도를 먼저 보고 일합니다. 고치거나 더할 것이 생기면 "지도 고쳐줘", "이것도 지도에 넣어줘"라고 말씀하세요.

채운 칸과 비운 칸을 한 줄씩 덧붙인다(예: "채움: 프로파일·지라·컨플루언스 프로젝트 / 비움: 자주 쓰는 채널"). 값 자체는 다시 나열하지 않는다.

## 주의

- 이 스킬과 템플릿에는 사내 URL·사내 이메일·private 플러그인 이름을 적지 않는다. 예시는 형식만 보인다.
- 지도 파일의 칸 형식(`## 제목` 다음 줄 `> 언제 읽나: …`)을 바꾸지 않는다. 세션 시작 훅이 이 형식을 읽는다.
