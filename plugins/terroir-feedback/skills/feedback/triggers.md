# [terroir-feedback] 떼루아 피드백 자동 제안 규칙

떼루아 스킬(`terroir-*`)을 쓰는 중 아래 상황이 생기면 떼루아 팀에 피드백을 보낼지 묻는다. 동의하면 `terroir-feedback:feedback` 스킬을 호출한다.

| 상황 | 분류 |
|---|---|
| 떼루아 스킬이 안내한 절차가 실패했다 (명령 오류 · 화면 주소 불일치 · 이어받기 실패) | `error` |
| 권한·접근이 막혀 진행할 수 없었다 (403 · 조직 접근 거부 · 플러그인 설치 실패) | `access_request` |
| 요청한 기능을 떼루아가 제공하지 않는다고 답했다 · 사용자가 번거롭다·불편하다고 말했다 | `feature_request` |
| 사용자가 결과가 기대와 다르다고 말했다 ("원래 이렇게 되는 게 아닌데", "안 되네" 류) | 대화로 판단 |
| 사용자가 떼루아 팀에 알리거나 요청하고 싶다고 말했다 | 묻지 않고 바로 호출 |
| 위 어디에도 없지만, 떼루아가 무엇을 고쳐야 할지 지목할 수 있는 마찰을 발견했다 | 대화로 판단 |

**마지막 줄의 문턱** — 고칠 대상을 지목할 수 있을 때만 묻는다. "안내받은 화면에 그 메뉴가 없다" · "같은 요청에 라우팅이 세 번 틀렸다" 는 고칠 자리가 있다. "사용자가 답답해 보인다" · "작업이 오래 걸렸다" 는 없다. 지목할 수 없으면 리포트 본문도 채울 수 없으므로 묻지 않는다.

**언제 묻나** — 그 턴 안에서. 사용자 요청을 먼저 처리하고 답변 맨 끝에서 묻는다. 다른 스킬로 넘기며 턴이 끝난다면 넘기기 직전에 묻는다. 다음 턴으로 미루지 않는다 — 미루면 잊는다.

**어떻게 묻나** — 단독 AskUserQuestion 으로 띄운다. 다른 질문에 두 번째 질문이나 선택지로 끼우지 않는다 — 함께 거절되면 물어본 적조차 없는 것이 된다.

**애매하면 묻는다.** 표의 앞 다섯 줄에 해당하면 보낼 값이 있는지 판단하지 않는다 — 사용자가 미리보기에서 승인해야 나가므로 걸러내는 것은 사용자 몫이다. Claude 가 요청을 오해했거나 라우팅을 틀린 경우도 제외하지 않는다 — 그 스킬의 안내나 라우팅 표가 부족했다는 신호다. 값을 판단하는 것은 마지막 줄뿐이다.

제한: 자동 제안은 세션당 최대 1회. 거절하면 그 세션에서 다시 묻지 않는다. 진행 중인 작업을 되돌리거나 버리지 않는다 — 요청은 그대로 처리하고 질문만 덧붙인다. 사용자 프로젝트 자체의 오류(테스트 실패 · 빌드 오류 등)는 떼루아 문제가 아니므로 제안하지 않는다. 자동 제안 경로에서 `other` 는 고르지 않는다.
