# feedback — 떼루아 피드백 보내기

**정리하고 · 보여주고 · 승인받아 보낸다.** 승인 없이 보내지 않고, 승인받은 내용 외에는 보내지 않는다.

## 원칙

- **템플릿을 채운다.** `./report-template.md` 의 형식과 채우기 규칙을 따른다. 항목을 빼거나 순서를 바꾸지 않는다.
- **대화에서 먼저 채우고, 모르는 것만 묻는다.** 기대한 동작·실제 동작·재현 순서는 대부분 직전 대화에 있다. 빈칸이 남으면 그 항목만 AskUserQuestion 으로 묻는다. 이미 아는 것을 다시 묻지 않는다.
- **전송 내용은 사용자가 본 것과 같다.** 미리보기에 보인 값을 그대로 `report.json` 에 옮겨 `send.sh` 에 넘긴다. 승인 뒤에 내용을 고치거나 더하지 않는다. 채널에는 카드 형식으로 도착하지만 항목과 값은 같다.
- **넣지 않는 것을 지킨다.** 대화 전체 · 사용자 프로젝트 코드 · 자격증명. 사용자가 붙여 달라고 해도 자격증명은 넣지 않는다. 떼루아 파일의 해당 한두 줄은 예외다 — 「추정 원인」·「해결방안」이 그 자리를 지목해야 성립한다.
- **취소하면 아무것도 나가지 않는다.** 취소 시 `send.sh` 를 호출하지 않는다. 임시 파일만 지운다.

## 절차

### 1. 분류와 재료 모으기

1. 분류를 정한다 — `./report-template.md` 「분류를 고르는 순서」를 따른다. 직전 대화로 판단이 서면 정하고, 애매하면 AskUserQuestion 으로 고르게 한다.

   **선택지는 셋이다** — 에러·오동작 / 기능 요청 / 권한 요청. 「기타」를 선택지로 만들지 않는다. AskUserQuestion 이 "Other" 항목을 자동으로 붙이므로, 사용자가 그것을 고르면 입력한 텍스트를 `content` 로 삼아 `other` 로 기록한다.

2. 관련 스킬·단계를 적는다. 스킬 실행 중이었다면 그 스킬 이름, 아니면 맵 단계 이름(기획 · 개발 등).
3. 직전 대화에서 템플릿 항목을 채운다. 오류 문구가 있으면 그대로 옮긴다.
4. 분류가 `error` 또는 `access_request` 면 「추정 원인」과 「해결방안」을 채운다.

   **이 두 항목의 독자는 플랫폼 개발팀이다.** 떼루아 파일이나 화면을 실제로 확인해 레포·경로·행 번호와 재현 조건을 남긴다. 확인하지 못했으면 `확인하지 못함` 을 적는다 — 추측을 확인한 것처럼 적지 않고, 빈칸으로 두지도 않는다.

5. 분류가 `access_request` 면 「누구」를 확인한다 — 본인만인지 · 팀 전체인지 · 다른 사람 몫인지. 신고자 이메일로 자동 채우지 않는다.
6. 환경 한 줄을 받는다.

        bash "${CLAUDE_PLUGIN_ROOT}/skills/feedback/scripts/collect-env.sh"

7. 신고자 이메일을 받는다 — `git config user.email`. 없으면 묻는다.
8. 빈칸이 남으면 그 항목만 묻는다. 한 번에 묻는다 — 항목마다 따로 질문을 띄우지 않는다.

### 2. 미리보기와 승인

채운 리포트 전문을 AskUserQuestion 의 `question` 에 담아 띄운다. **본문을 텍스트로 따로 출력하지 않는다** — 같은 턴에 도구 호출이 이어지면 텍스트가 접혀 사용자에게 보이지 않는다.

질문 형식 — 아래 전체가 `question` 값 하나다.

```
아래 내용을 떼루아 팀 채널로 보냅니다. 소스코드·비밀값이 섞여 있지 않은지 확인해 주세요.

────────────────────────────────
{리포트 전문}
────────────────────────────────

이대로 보낼까요?
```

`header` 는 "피드백", 선택지는 셋이다.

```
선택지: 보내기 / 수정하기 / 취소
```

- **보내기** → 3 으로.
- **수정하기** → 무엇을 고칠지 자유 입력으로 받아 반영한 뒤 미리보기를 다시 띄운다. 횟수 제한 없음.
- **취소** → 임시 파일을 지우고 "보내지 않았습니다" 한 줄로 종료한다. 그 세션에서 다시 제안하지 않는다.

### 3. 전송

1. 미리보기에서 승인한 값으로 `report.json` 을 만든다. 필드는 `./report-template.md` 「report.json」 절과 같다. 경로는 세션 스크래치 디렉터리 또는 `${TMPDIR:-/tmp}/terroir-feedback-<timestamp>.json`.
2. 전송한다.

        bash "${CLAUDE_PLUGIN_ROOT}/skills/feedback/scripts/send.sh" <report.json>

3. 결과를 알린다.
   - 첫 줄이 `OK <ID>` → "접수됐습니다. ID: <ID>" 한 줄. 팀이 이 ID 로 회신할 수 있다고 덧붙인다.
   - 첫 줄이 `FAIL <ID> <경로>` → 보내지 못했다고 알리고, 저장 경로와 채널 링크(스크립트 출력 둘째 줄)를 그대로 보여준다. 사용자가 채널에 직접 붙여 넣을 수 있게 미리보기 텍스트를 코드블록으로 한 번 출력한다. 재시도는 사용자가 원할 때만 한다.
4. 임시 파일을 지운다.

## 리포트 ID

`send.sh` 가 만든다 — `YYYYMMDD-HHMM-xxxx`. 카드의 「환경 · 신고 정보」 섹션에 들어간다. 미리보기에는 없고, 전송 결과에서 사용자에게 알린다.

## 하지 않는 것

- 리포트를 여러 건 묶어 보내지 않는다. 한 번에 한 건이다.
- 팀의 답을 기다리거나 조회하지 않는다. 채널은 단방향이다.
- 사용자 프로젝트의 버그를 대신 신고하지 않는다. 떼루아(플러그인 · 포털 · 표준) 관련만 받는다. 아니면 한 줄로 알리고 종료한다.
