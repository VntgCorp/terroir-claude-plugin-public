# 리포트 템플릿

리포트는 두 형태로 존재한다. **미리보기(텍스트)** 는 사용자가 AskUserQuestion 에서 보는 것이고, **report.json** 은 `send.sh` 가 카드로 바꿔 보내는 것이다. 항목은 1:1 이다 — 미리보기에서 승인한 값만 JSON 에 넣는다.

`{ }` 자리를 채운다. 빈칸을 비워 두지 않는다 — 모르면 사용자에게 **그 항목만** 묻는다.

## 미리보기 — 에러 · 없는 기능

```
{이모지} {한 줄 제목}
{분류} · {스킬} · {맵 단계}

기대
  {사용자가 기대한 동작 — 1~2문장}
실제
  {실제로 일어난 일 — 에러 문구가 있으면 요약하지 않고 그대로}
재현
  1. {첫 행동}
  2. {다음 행동}
  3. {결과가 나온 지점}

신고 {이메일} · 환경 {collect-env.sh 출력}
```

## 미리보기 — 기능 요청

```
💡 {한 줄 제목}
기능 요청 · {관련 스킬 또는 단계}

원하는 것
  {무엇을 할 수 있게 되길 원하나 — 1~2문장}
지금은
  {지금은 어떻게 우회하거나 못 하고 있나}
왜 필요한가
  {어떤 상황에서 반복되는 불편인가}

신고 {이메일} · 환경 {collect-env.sh 출력}
```

## report.json

```json
{
  "category": "error | missing | request",
  "title": "증상 한 줄 — 분류·스킬 이름은 넣지 않는다",
  "skill": "deploy-config",
  "stage": "5 DEPLOYMENT",
  "expected": "…", "actual": "…", "repro": ["…", "…", "…"],
  "want": "…", "now": "…", "why": "…",
  "reporter": "user@vntgcorp.com",
  "env": "private 8b8a07e (8) · public 20523f7 (2) · Claude Code 2.1.250 · macOS (arm64)"
}
```

`expected/actual/repro` 는 error·missing 에, `want/now/why` 는 request 에만 넣는다. 리포트 ID 는 `send.sh` 가 만들어 카드에 넣는다 — JSON 에 넣지 않는다.

## 채우기 규칙

| 항목 | 규칙 |
|---|---|
| 이모지·분류 | 🐞 에러 `error` / 🚫 없는 기능 `missing` / 💡 기능 요청 `request` |
| 제목 | 증상만. "배포 롤백 안내 없음" ○ / "deploy-config: 배포 롤백 안내 없음" ✕ / "안 됨" ✕ |
| 스킬 | 실행 중이던 스킬 이름. 없으면 플러그인 이름, 그것도 없으면 빈 문자열 |
| 맵 단계 | `1 KICKOFF` ~ `6 OBSERVABILITY`, `0 SETUP`. 단계와 무관하면 빈 문자열 |
| 실제 | 에러 문구는 그대로 넣는다. 팀이 검색할 수 있어야 한다 |
| 재현 | 사용자가 실제로 한 순서. 추측으로 채우지 않는다. 항목 하나가 한 행동 |
| 이메일 | `git config user.email`. 없으면 묻는다 |
| 길이 | 항목마다 3문장 이내. 로그가 길면 핵심 줄만 |

## 넣지 않는 것

- 대화 전체 · 소스코드 본문 · 파일 내용
- 토큰 · 비밀번호 · API 키 · webhook URL 등 자격증명
- 사용자 프로젝트의 고객 데이터

전송 전 미리보기에서 사용자가 위 항목이 섞였는지 확인한다. 이것이 승인 단계의 목적이다.
