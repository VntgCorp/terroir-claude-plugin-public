# terroir-harness-mesh

> 내가 모은 자료를 **상호링크된 위키**로 자동 정리해 주고, 나중에 **근거 기반으로 답**해 주는 개인 지식 베이스 플러그인.

자료를 던지면(`save`) 알아서 위키 페이지로 컴파일하고(`ingest`), 물어보면 저장된 내용만 근거로 답하며(`query`), 문서 건강검진까지(`lint`) 해 준다. 데이터는 전부 내 컴퓨터의 평문 마크다운 파일이라 Obsidian으로 열어 그래프 뷰로 볼 수도 있다.

## 왜 쓰나

- **모으기만 하면 정리는 자동.** 링크·메모·텍스트를 던져 두면 요약·핵심·열린 질문이 담긴 위키 페이지로 컴파일되고, 관련 페이지끼리 자동으로 링크된다.
- **거짓말하지 않는 검색.** 질문하면 저장된 자료에서만 근거를 찾아 인용해 답한다. 근거가 없으면 지어내지 않고 "근거 없음"이라고 답한다.
- **항상 내 손안에.** 모든 데이터는 로컬 평문 마크다운(`~/harness-mesh-storage`)이다. 잠금(lock-in) 없고, git으로 이력이 남고, Obsidian 그래프 뷰와 호환된다.

## 요구사항

- Claude Code + terroir 플러그인 마켓
- `git`, `python3` (기계 검사 `lint.py`는 표준 라이브러리만 사용)
- **[Obsidian](https://obsidian.md) 권장**: storage가 평문 마크다운이라 Obsidian으로 열면 그래프 뷰로 상호링크를 시각화할 수 있다(선택).
- **Windows 사용자**: 스크립트가 bash로 동작한다. [Git for Windows](https://git-scm.com/download/win)를 설치하고, Claude Code가 bash를 못 찾으면 환경변수 `CLAUDE_CODE_GIT_BASH_PATH`에 `bash.exe` 경로를 지정한다(예: `C:\Program Files\Git\bin\bash.exe`). WSL을 써도 되며, 이 경우 storage는 WSL 홈에 생성된다.

## 설치

1. terroir 플러그인 마켓에서 **`terroir-harness-mesh`**를 활성화한다.
2. 아무 동작이나 한번 부른다(예: "mesh에 저장해줘"). storage가 아직 없으면 자동으로 생성을 제안한다.
3. 승인하면 `~/harness-mesh-storage`가 만들어지고 `git init`까지 끝난다. 이후 바로 사용 가능.

> storage 생성은 최초 1회뿐이다. 데이터 골격(빈 inbox/raw/wiki + index.md + log.md)만 깔리고, 로직(스킬)은 복사되지 않는다.

## 빠른 시작

```
나: 이 글 mesh에 저장해줘 — <붙여넣기 또는 URL/파일>
   → inbox에 저장 후 곧바로 위키 페이지로 컴파일됨

나: mesh에서 키보드 매트릭스 스캔 어떻게 동작하는지 찾아줘
   → 저장된 페이지를 근거로 [[링크]] 인용해 답변

나: mesh 건강검진해줘
   → 깨진 링크·고아·낡은 내용·모순을 점검·정리
```

## 사용법

동작은 자연어로 부르면 된다. `/harness-mesh` 슬래시로도 호출할 수 있다.

### 4개 동작 한눈에

| 동작 | 무엇 | 트리거 예시 |
|------|------|-------------|
| **save** | 자료를 inbox에 저장 → **자동으로 ingest까지 연쇄** | "mesh에 저장해줘", "이거 storage에 넣어줘" |
| **ingest** | inbox의 자료를 위키 페이지로 컴파일 (보통 save가 자동 호출) | "mesh ingest", "지식그물 컴파일해줘" |
| **query** | 저장된 내용을 근거로 질문에 답 (없으면 "근거 없음") | "mesh에 물어봐", "storage에서 찾아줘" |
| **lint** | 문서 건강검진 — 깨진 링크·고아·낡음·모순 점검 | "mesh lint", "storage 건강검진" |

### 저장하기 (save)

자료(텍스트·파일·URL·메모)를 주면 `inbox/`에 저장한 뒤, **같은 실행에서 곧바로 위키로 컴파일**한다. 따로 스케줄러를 켜지 않아도 저장 즉시 페이지가 생긴다.

```
나: 방금 정리한 CPU 캐시 계층 내용 mesh에 저장해줘
   → save: inbox에 저장
   → ingest: source 페이지 + 'CPU 캐시 계층' concept 페이지 생성, 관련 페이지와 교차링크
```

한 자료를 넣으면 **요약·핵심(takeaway)·열린 질문**이 담긴 source 페이지 1개와, 거기 언급된 대상마다 entity/concept 페이지가 만들어지고 서로 링크된다.

### 질문하기 (query)

```
나: mesh에서 shim 아키텍처가 뭔지 알려줘
   → 저장된 페이지를 정독하고 [[shim-architecture]]를 인용해 답변
```

핵심: **저장된 근거 안에서만 답한다.** storage에 관련 내용이 없으면 추측하지 않고 "근거 없음"이라고 정직하게 말한다. 답변 중 보존할 가치가 있는 합성 결과는 note 페이지로 저장을 제안할 수 있다.

### 건강검진 (lint)

```
나: mesh 건강검진해줘
   → ① 기계 검사(lint.py): 깨진 링크, index 누락/중복, frontmatter 오류 등
   → ② 의미 진찰: 모순되는 주장, 낡은 내용(stale), 고아 페이지를 사람 검토용으로 목록화
```

기계적으로 고칠 수 있는 건 자동 정정하고, 판단이 필요한 항목은 "사람 검토 필요" 목록으로 보고한다.

### 수동 컴파일 (ingest)

평소엔 save가 자동으로 호출하므로 직접 부를 일이 드물다. inbox에 처리 안 된 자료가 쌓여 있을 때 "mesh ingest"로 수동 컴파일할 수 있다. 한 번에 가장 오래된 1건(지시하면 최대 3건)을 처리한다.

## 데이터는 어디에 쌓이나

모든 데이터는 `~/harness-mesh-storage` 한 곳에 평문 마크다운으로 쌓이고, 로컬 git으로 이력이 관리된다.

```
~/harness-mesh-storage/
├── inbox/     ← 아직 컴파일 안 된 자료 (내가 넣는 곳)
├── raw/       ← 컴파일 끝난 원본 보관 (불변)
├── wiki/      ← 상호링크된 위키 페이지 (에이전트가 관리)
├── index.md   ← 전체 목차
└── log.md     ← 처리 연대기
```

- **push는 자동으로 하지 않는다.** 로컬 전용이며 원격 연결은 직접 결정한다.
- `.obsidian/`은 git에서 제외되므로 Obsidian으로 열어 그래프 뷰를 그대로 쓸 수 있다.

## (예정) 무인 자동화 — drain

> **현재 미제공 — 추후 제공 예정.** inbox에 쌓인 자료를 주기적으로 자동 컴파일하는 무인 모드(OS 스케줄러 기반)는 설계는 마쳤으나 이번 배포에는 포함되지 않는다.

지금도 **`save` 하면 곧바로 `ingest`까지 자동 연쇄**되므로, 저장하는 순간 위키로 컴파일된다 — 별도 스케줄러 없이도 즉시 정리된다. 무인 일괄 모드는 다음 배포를 기다려 달라. 설계 개요는 [ARCHITECTURE.md §6](./ARCHITECTURE.md#6-무인-운용--drain-루프) 참조.

## 자주 묻는 문제

| 증상 | 원인 / 해결 |
|------|-------------|
| 저장하려는데 "storage가 없다"고 함 | 최초 1회 setup 미진행 — 생성 제안을 승인하면 `~/harness-mesh-storage`가 만들어진다 |
| "스킬 로직을 못 찾음(NO_SKILL_LOGIC)" | 플러그인 설치·경로 문제 — 플러그인이 정상 활성화됐는지 확인 |
| 질문했는데 "근거 없음"이라고만 답함 | 설계상 정상 — 저장된 자료에 근거가 없으면 지어내지 않는다. 먼저 관련 자료를 save하라 |
| Windows에서 스크립트가 안 돈다 | bash 미설치 — [요구사항](#요구사항)의 Git for Windows / `CLAUDE_CODE_GIT_BASH_PATH` 설정 확인 |
