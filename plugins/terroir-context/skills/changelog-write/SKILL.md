# CHANGELOG 항목 쓰기

규칙은 이 스킬에 옮겨 적지 않는다. **원본은 `../../docs/changelog-writing.md` 하나다**(이 스킬 디렉터리 기준).
두 곳에 두면 한쪽만 고쳐져 어긋난다.

## 절차

1. **원본을 읽는다.** `../../docs/changelog-writing.md` 를 처음부터 끝까지 읽는다. 기억으로 쓰지 않는다.
2. **그 저장소가 고른 값을 찾는다.** 원본의 「갈릴 수 있는 것」 여섯은 저장소마다 답이 다르다.
   저장소의 `docs/` · `CONTRIBUTING.md` · 버전 규칙 문서에서 CHANGELOG 를 다루는 곳을 찾아 읽는다.
   원본과 다르게 적힌 것이 있으면 사용자에게 알린다 — 어느 쪽을 따를지는 사용자가 정한다.
3. **이번에 달라진 것만 모은다.** 직전 버전(또는 마지막 릴리즈 태그)과 이번 변경을 비교한다.
   중간에 바꿨다가 되돌린 것, 아직 배포되지 않은 기능을 만드는 중의 수정은 넣지 않는다(규칙 8).
4. **초안을 쓴다.** 원본의 규칙 1~7 과 「어디에 적나」를 따른다. 커밋 메시지·PR 본문에 갈 내용은 빼서 따로 알린다.
5. **「쓰기 전 확인」을 전부 통과시킨다.** 항목마다 두 묶음을 훑고, 「아니오」가 나온 항목은 고친다.
6. **사람에게 보여 준다**(규칙 9). 초안과 함께 확인에서 고친 것을 한 줄씩 알리고, 승인을 받은 뒤 파일에 쓴다.

## 하지 않는 것

- 버전 번호를 정하지 않는다. 그 저장소의 버전 규칙이 정한다.
- 기존 항목을 사용자가 요청하지 않았는데 고치지 않는다. 규칙에 어긋난 기존 항목을 보면 알리기만 한다.
