# 떼루아 용어

떼루아에서 정해 쓰는 말의 개념 · 용어 · 의미를 적은 문서입니다. 다른 문서와 플러그인은 이 내용을 다시 쓰지 않고 이 문서를 읽습니다.

이 문서가 원본이고 사본은 없습니다. 스킬은 세션 시작 때 받은 이 폴더의 경로로 이 문서를 읽어 문장을 그대로 보여 줍니다.

## 1. 프로젝트 · 애플리케이션 · 워크로드

### 개념

만든 소프트웨어는 세 단계로 담깁니다. 가장 바깥이 프로젝트, 그 안이 애플리케이션, 가장 안쪽이 워크로드입니다. DB 는 애플리케이션 안이 아니라 프로젝트에 붙습니다.

```
프로젝트 book-rental                 누가 무엇에 접근하나 — 권한 · 데이터의 경계
├── 애플리케이션 book-rental          무엇을 만들어 배포하나 — 포털 앱 · 레포 · 배포 탭
│   ├── 워크로드 be-api-server       서버        → 배포 탭 카드
│   ├── 워크로드 fe-user-client      화면        → 배포 탭 카드
│   └── 워크로드 overdue-notice      정기 작업   → 배포 탭 카드
└── DB book-rental-db                프로젝트의 애플리케이션이 함께 씀
```

예시는 가상의 도서 대여 앱입니다.

- **프로젝트**는 접근의 경계입니다. 같은 프로젝트의 애플리케이션은 권한과 DB 를 함께 씁니다.
- **애플리케이션**은 무엇을 만들어 배포하는지의 단위입니다.
- **워크로드**는 실제로 돌아가는 것입니다. 배포 · 일시정지 · 되돌리기를 워크로드마다 따로 합니다.

### 용어와 의미

| 용어 | 의미 |
|---|---|
| 프로젝트 | 함께 운영하는 소프트웨어를 묶는 가장 큰 단위입니다. 같은 프로젝트의 애플리케이션은 권한과 DB 를 함께 씁니다 |
| 애플리케이션 | 포털에서 만든 앱 하나입니다. 보통 레포 하나와 짝이고, 포털에 배포 탭이 하나 생깁니다 |
| 워크로드 | 애플리케이션 안에서 따로 빌드해서 따로 실행하는 단위입니다 — 서버 하나, 화면 하나, 정기 작업 하나. 배포 탭에 워크로드마다 카드가 하나 생깁니다 |
| DB | 애플리케이션에 들지 않고 프로젝트에 붙습니다. 포털의 프로젝트 화면에서 `＋ DB 추가` 로 받고, 같은 프로젝트의 애플리케이션이 함께 씁니다 |

애플리케이션 곁에 DB 를 직접 두는 것은 **로컬 개발에서만** 합니다(`make infra-up` 이 띄우는 로컬 postgres). 배포 환경에서는 그렇게 하지 않습니다 — 「클러스터에 직접 띄우거나, 이미 있는 외부 DB 를 그대로 쓰는 길도 있습니다. 둘 다 신규 프로젝트에는 권장하지 않습니다.」(온보딩 레슨 「프로젝트를 만들어 첫 배포까지」)

## 2. PRD · FRD

### 개념

기획은 두 문서로 나눠 씁니다. PRD 에서 제품 전체를 정하고 기능으로 나누면, 나눈 기능마다 FRD 를 하나씩 씁니다. 기능 하나만 정리할 때는 PRD 없이 FRD 만 써도 됩니다.

```
PRD   제품 전체에 하나     무엇을 왜 만들고, 어떤 기능으로 나누나
├── FRD  기능 1           이 기능이 어떻게 동작하고, 무엇이 되면 완성인가
├── FRD  기능 2
└── FRD  기능 3
```

개발로 넘기는 것은 이 두 문서입니다.

### 용어와 의미

| 용어 | 의미 |
|---|---|
| 제품 요구사항 문서(PRD) | 제품 전체에 하나 — 무엇을 왜 만들고 어떤 기능으로 나눌지 정합니다 |
| 기능 요구사항 문서(FRD) | 기능마다 하나 — 그 기능이 어떻게 동작하고 무엇이 되면 완성인지 정합니다 |

다른 문서에서 FRD 를 풀어 쓸 때도 「기능 요구사항 문서」 로 씁니다.
