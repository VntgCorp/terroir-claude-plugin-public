# 떼루아 구성요소 버전 규칙

떼루아가 만들어 배포하는 구성요소(템플릿 · 플러그인 · KMM · 포털 · SDK)의 버전 번호를 언제 어느 자리까지 올리는지 정한 문서입니다.
이 문서가 원본이고 사본은 없습니다. 다른 저장소의 안내와 결정 기록은 이 문서를 가리킵니다.

사용자 애플리케이션의 버전(`terroir.json` 의 `version`)은 이 문서의 대상이 아닙니다. 그 번호는 terroir-project-context 의 「애플리케이션 버전 관리」(`getting-started/app-versioning.md`)를 따릅니다.

## 규칙 요약

| 자리 | 올리는 조건 |
|---|---|
| 메이저 | 평소에는 올리지 않습니다. 지금 메이저 안에서 호환을 지킬 방법이 없을 때만 팀장과 논의해 올리고 그 결정을 기록합니다 |
| 마이너 | 사용자가 쓰는 것이 생기거나 없어질 때(스킬 · 명령 · 템플릿 선택지 · 설정 항목 · API 라우트 · 필드의 추가 · 제거 · 이름 변경), 기존 사용자가 손대야 하는 변경 |
| 패치 | 그 밖의 모든 변경 — 버그 · 보안 수정, 사용자 환경을 바꾸지 않는 의존성 상향, 내부 리팩터, 산출물에 들어가는 문서 · 문구 |

- 사용자가 받는 산출물(템플릿 · CLI · 플러그인 파일 · 배포되는 코드)을 바꾸는 PR 이 번호를 올립니다. 레포지토리의 README · CHANGELOG · ADR 만 고친 PR 은 올리지 않습니다.
- 한 PR 에 여러 변경이 있으면 가장 높은 자리 하나만 올립니다. 먼저 머지된 PR 과 번호가 겹치면 나중 PR 이 최신 번호 위로 다시 올립니다.
- 메이저로 판단되면 번호를 올리기 전에 멈추고 사람에게 확인합니다.
- 기존 사용자가 손대야 하는 변경은 이력(MIGRATIONS.md · CHANGELOG)에 `### 필수 조치` 절로 적습니다. 이 절이 있어도 번호는 마이너입니다.
- 이미 올라간 번호는 내리지 않습니다.

## 경계 사례

| 변경 | 자리 |
|---|---|
| 스킬 제거 · 이름 변경 | 마이너 |
| 환경변수 이름이 바뀌어 기존 레포지토리가 코드를 고쳐야 함 | 마이너 + 필수 조치 |
| Node 하한 상향으로 기존 레포지토리의 로컬 Node 를 올려야 함 | 마이너 + 필수 조치 |
| 보안 수정 | 패치. 급하다는 사실은 공지로 알립니다 |
| 플러그인 안의 문서 · 스킬 문구만 변경 | 패치. 플러그인은 버전이 바뀌어야 배포됩니다 |
| 레포지토리의 README · CHANGELOG · ADR 만 변경 | 올리지 않습니다 |

## 레포지토리별 번호 위치

| 레포지토리 | 번호의 정본 | 이력 | 함께 할 일 |
|---|---|---|---|
| gh-terroir-greenfield | `VERSION` | `MIGRATIONS.md` | terroir-reusable-workflow `check-bootstrap-version.yml` 의 `TERROIR_BOOTSTRAP_LATEST` 를 같은 값으로 올립니다. 어긋나면 사용자 레포지토리가 뒤처져도 경고를 받지 못합니다 |
| gh-terroir-byor | `VERSION` | `MIGRATIONS.md` | — |
| terroir-claude-plugin · terroir-claude-plugin-public | 플러그인마다 `.claude-plugin/plugin.json` 의 `version` | 플러그인 `CHANGELOG.md` | 마켓플레이스 최상위 `version` 과 CHANGELOG 형식은 그 레포지토리의 마켓플레이스 ADR 을 따릅니다 |
| terroir-kmm · RND-IDP | `package.json` 의 `version` | `CHANGELOG.md` (두는 레포지토리만) | — |
| terroir-sdk | 패키지마다 `src/**/package.json` 의 `version` | 릴리스 안내 | 아래 「npm 패키지 예외」 |

### npm 패키지 예외

`@vntgcorp/*` 패키지는 사용자가 `^` 범위로 받습니다. 호환을 깨고도 메이저를 올리지 않으면 깨진 버전이 사용자에게 자동으로 설치됩니다. 그래서 공개 API 의 호환을 깨면 SemVer 원칙대로 메이저를 올리고 마이너는 공개 API 추가 · 하위 호환되는 기능 추가에 씁니다. `0.x` 동안은 마이너가 메이저 역할을 합니다.

## 커밋 접두와 번호

커밋 접두(`feat` · `fix` · `docs` · `chore`)는 변경의 성격을 나타내고 번호 자리는 「규칙 요약」을 따릅니다. 기존 기능을 개선한 `feat` 은 패치입니다. 커밋 제목에 `!` 를 쓰지 않습니다.

## 메이저를 고정하는 이유

메이저 번호를 오래 유지하는 플랫폼은 그 번호를 호환 약속으로 씁니다. Go 는 2012년 Go 1 이후, Kubernetes 는 2015년 1.0 이후, Backstage 는 2022년 1.0 이후 메이저를 유지합니다.

- 같은 메이저 안이면 업그레이드해도 기존 것이 깨지지 않아 사용자가 업그레이드를 미루지 않습니다.
- 「1.x 기준」으로 쓴 문서 · 교육 · 도구를 오래 쓸 수 있습니다.
- 메이저가 드물게 오르면 사용자는 그때 다시 검토해야 한다고 받아들입니다.

메이저는 절대 올리지 않는 번호가 아니라 지금 메이저 안에서 호환을 지킬 방법이 없을 때만 올리는 번호입니다. 올릴 때는 옮기는 방법과 이전 메이저의 지원 기간을 함께 공지합니다.
