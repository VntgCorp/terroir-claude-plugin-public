# 버전 관리

내가 만들어 다른 사람이 쓰는 것의 버전 번호를 언제 어느 자리까지 올리는지 정한 문서입니다.
대상은 떼루아로 배포하는 애플리케이션(`terroir.json` 의 `version`)과 커뮤니티 마켓에 올리는 플러그인(`plugin.json` 의 `version`)입니다. 둘은 같은 기준을 씁니다.

이 문서가 원본이고 사본은 없습니다. 떼루아 팀이 만드는 템플릿 · 플러그인 · 포털의 번호는 이 문서의 대상이 아닙니다.

## 규칙 요약

| 자리 | 올리는 변경 |
|---|---|
| 메이저 | 쓰는 쪽이 고쳐야 하는 변경 — 호환이 깨집니다 |
| 마이너 | 쓰는 쪽이 새로 쓸 수 있는 것이 생기거나 없어지는 변경. 기존 것은 그대로 동작합니다 |
| 패치 | 그 밖의 변경 — 버그 · 보안 수정, 문구 수정, 의존성 상향 |

- 한 번에 들어간 변경 중 가장 큰 것 하나로 자리를 정합니다.
- 판단이 갈리면 메이저 쪽으로 봅니다. 올리지 않아 다른 사람의 작업이 깨지는 쪽이 더 비쌉니다.
- 이미 내보낸 번호는 다시 쓰지 않습니다.

쓰는 쪽은 메이저 번호를 보고 업그레이드할 때 손대야 하는지 판단합니다. 그래서 호환이 깨지면 메이저를 올립니다.

## 애플리케이션

애플리케이션 버전은 `terroir.json` 의 워크로드마다 있는 `version` 입니다. 이 값이 컨테이너 이미지 태그가 되고 운영에 어떤 릴리스가 나갔는지 알려 줍니다.

| 상황 | 할 일 |
|---|---|
| 형식 | `v` 로 시작하는 세 자리 번호 — `v1.4.2`. CI 가 형식을 검사합니다 |
| 처음 만들 때 | 템플릿은 `v0.0.1` 로 시작합니다. 운영(PROD)에 처음 배포할 때 `v1.0.0` 으로 올리고 그때부터 「규칙 요약」을 적용합니다 |
| DEV 브랜치에서 개발 중 | 올리지 않아도 됩니다. 이미지 태그에 붙는 빌드 시각이 빌드 회차를 구분합니다 |
| PROD 브랜치로 머지하는 PR | 바뀐 워크로드의 `version` 을 이번 릴리스 번호로 확정합니다 |
| 운영 긴급 수정 | 패치를 올립니다. 같은 번호로 PROD 에 두 번 배포하지 않습니다 |
| 워크로드가 여럿일 때 | 바뀐 워크로드만 올립니다. 워크로드끼리 번호를 맞추지 않아도 됩니다 |

애플리케이션에서 메이저는 API 응답 형식 변경, 엔드포인트 제거, 되돌릴 수 없는 데이터 구조 변경입니다. 마이너는 새 화면 · 새 API · 쓰지 않는 기능 제거입니다.

이미지 태그는 `version` 뒤에 빌드 시각(KST)을 붙여 만들어집니다 — `v1.4.2-261110.143005`. 떼루아는 형식만 검사하고 번호를 자동으로 올리거나 같은 번호가 이미 운영에 나갔는지 검사하지 않습니다.

`terroir.json` 의 `schema` 는 파일 형식의 번호이고 떼루아가 정합니다. 애플리케이션 버전을 따라 올리지 않습니다.

## 커뮤니티 마켓 플러그인

플러그인 버전은 `.claude-plugin/plugin.json` 의 `version` 입니다. Claude Code 는 이 값이 바뀌어야 설치한 사람에게 새 파일을 내려보냅니다. 그래서 사용자에게 닿는 파일(`skills/` · `agents/` · `commands/` · `hooks/` · `scripts/` · `references/` · `templates/`)을 고친 PR 은 같은 PR 에서 번호를 올립니다. `README.md` · `CHANGELOG.md` 만 고친 PR 은 올리지 않습니다.

| 변경 | 자리 |
|---|---|
| 스킬 이름을 바꾸거나 없앴다 | 메이저. 쓰던 사람의 `/명령`이 사라집니다 |
| 기존 산출물을 새 버전이 읽을 수 없다 · 사용자가 설정을 고쳐야 한다 | 메이저 |
| 훅을 추가했다 | 메이저. 설치 환경이 바뀝니다 |
| 스킬을 하나 더했다 · 기존 스킬에 할 수 있는 일을 더했다 | 마이너 |
| `description` 만 바꿨다 | 패치. 트리거 조건이 달라져 뜨지 않던 곳에서 뜨면 마이너 |
| 버그를 고쳤다 · 안내 문구를 다듬었다 · 스킬이 읽는 참조 문서를 고쳤다 | 패치 |

번호를 올리는 절차와 CHANGELOG 를 쓰는 자리는 커뮤니티 마켓 레포지토리의 `docs/versioning.md` 에 있습니다.

## AI 어시스턴트가 지키는 규칙

- PROD 브랜치로 가는 PR 에서 바뀐 워크로드의 `version` 이 기준 브랜치보다 올라가 있지 않으면 어떤 번호로 확정할지 사람에게 묻습니다. 번호를 임의로 정하지 않습니다.
- DEV 브랜치로 가는 PR 에서는 `version` 을 올리라고 요구하지 않습니다.
- 플러그인의 사용자에게 닿는 파일을 고쳤는데 `version` 이 그대로면 올릴 자리를 판정해 제안합니다. 메이저면 그 이유를 함께 알립니다.
