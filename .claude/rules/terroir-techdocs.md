# Terroir 표준 — 프로젝트 문서(TechDocs)

> Managed by gh-terroir-byor. 사내 표준 변경 시 재실행으로 갱신됩니다. 직접 수정하지 마세요.

이 레포의 `docs/` 와 `mkdocs.yml` 은 Backstage 의 Docs 탭에 그대로 노출되는 문서 원본이다.
CI 가 이 둘을 정적 사이트로 빌드해 발행하므로, 파일 구조가 규약에서 벗어나면 문서가 아예
뜨지 않거나 링크가 깨진 상태로 게시된다. 아래 규약을 지킨다.

## 건드리면 안 되는 것

- `mkdocs.yml` 의 `plugins` 에서 `techdocs-core` 를 제거하지 않는다. Backstage 표준 테마·확장
  묶음이라 빠지면 렌더가 깨진다.
- `mkdocs.yml` 의 `validation.links` 설정을 낮추지 않는다. 깨진 링크를 PR 단계에서 잡는 장치다.
- `.github/workflows/terroir-techdocs.yml` 은 managed 파일이다. 직접 고치지 않는다.

## 문서를 추가·수정할 때

- 새 문서는 `docs/` 아래에 만들고 **반드시 `mkdocs.yml` 의 `nav` 에 등록한다.** nav 에 없는
  파일은 사이트에 나타나지 않고, nav 에만 있고 실제 파일이 없으면 빌드가 실패한다.
- 문서 간 링크는 파일 상대경로 마크다운으로 쓴다(예: `[운영 가이드](./operations.md)`).
  존재하지 않는 파일을 가리키면 PR 검증에서 빌드가 중단된다.
- 앵커 링크(`./operations.md#배포-절차`)를 쓸 때는 대상 문서에 그 제목이 실제로 있는지 확인한다.
- 이미지는 `docs/` 아래에 함께 두고 상대경로로 참조한다. 레포 밖 경로나 절대경로는 쓰지 않는다.
- 문서 파일을 지우거나 이름을 바꿀 때는 `nav` 항목과 그 문서를 가리키던 링크를 함께 고친다.

## 확인 방법

머지 전에 로컬에서 같은 검사를 돌릴 수 있다.

```bash
pip install mkdocs-techdocs-core==1.7.0
mkdocs build --strict     # PR 검증과 동일한 검사
npx @techdocs/cli serve --no-docker   # 브라우저로 미리보기
```

## Backstage 화면에서 문서를 고칠 때

발행된 문서 페이지 오른쪽 위에 연필 아이콘("Edit this page")이 있다. 누르면 이 레포의 해당
마크다운 편집 화면으로 이동한다. 기본 브랜치가 보호돼 있으면 GitHub 이 새 브랜치와 PR 을
만들도록 안내한다.

이 레포에 브랜치 이름 규약이나 PR 흐름 정책이 있다면, GitHub 이 제안하는 기본 이름
(`<사용자>-patch-1`)을 그 규약에 맞게 바꿔서 쓴다.

## 배경

- 문서 원본의 단일 출처는 이 레포다. 발행된 사이트는 파생 사본이라 지워져도 재발행으로 복구된다.
- 발행은 **이 레포의 기본 브랜치** 하나에서만 일어난다. 기본 브랜치가 아닌 브랜치로 들어온
  push 는 발행 워크플로가 조용히 건너뛴다. 저장 경로가 카탈로그 엔티티 하나에 대응하므로
  브랜치별 사이트가 존재할 수 없다.
- Backstage 는 문서를 직접 빌드하지 않는다. 빌드 주체는 이 레포의 CI 다.
